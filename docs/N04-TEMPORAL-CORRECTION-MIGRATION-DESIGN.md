# N04 纠正、冲突与时间闭环：只读迁移设计

本文件是现有代码的结构核查与下一步迁移契约草案。不执行 DDL、不回填、不写生产、不自动
更正旧判断。正式 SQL、迁移号和部署计划需在此契约评审后单独交付并恢复演练。

## 已有基础与缺口

records 已有 immutable revision / supersedes / lifecycle，governance 有 holder / subject_id /
as_of / valid_until / state / revision，events 与 governance_events 保留操作者与系统记录时间。
owner_memory.revise 保留旧版与来源，更新正文或只更新治理位都不原地抹去历史。
memory_context 已有 context_revision，能在新请求发现可信集合变化；不是客户端撤回通知。

当前 created/reviewed/event created 只说明系统何时入库或审核，不证明事实在世界上何时成立、
失效，也不足以保证完整双时间追溯。valid_until 是排他终点，当天已不作为当前有效。
旧 as_of 空值保持未知。来源日期不能自动填成立时间，旧更正事件不能自动填事实失效时间。

## 收敛的业务契约

**两条时间轴：**事实期 valid_from / valid_until 表示主张适用的时间；系统期 recorded_at /
retired_at 表示这版判断何时进入/退出系统可用集合。每个时间位允许未知，并标记是否有出处。
当前 as_of 沿用为 valid_from 的兼容投影，不能用入库日期回填空值。

**三种变化不同：**补充证据或元数据、本人纠正原理解、本人真实观点改变。前两者说明系统
理解改变，第三者才可能提供事实期的明确终点。动作类型与理由需审计，不靠文本差异猜测。
审核 verified 也不等于用户采纳了所有助手建议；核实的是具体带归属的那一条判断。

**冲突是待核查关系：**同 owner + scope + holder + subject_id 且事实期可能重叠，才生成冲突
线索；不同人的不同观点并存，不互相 supersede。未知 holder 或日期先 unresolved，不猜合并。
语义矛盾、适用场景不同与条件差异须核实。Agent 可以提建议，不能自动裁决或借此升级治理。

## 最小新增结构提案

优先追加审计侧表，而非替换 records / governance 真源。拟保存 record_id、预期record及
governance revision、change_kind、明确的 valid_from / valid_until、recorded_at、关联旧版本、
reason_source_id/message_id、actor、request_key；一切推测的时间仍为空。

系统期由追加事件与版本链派生，并注明追溯起点。迁移前旧资料缺历史事件时标记
legacy_incomplete，不宣称能恢复过去任意时刻的系统判断。草案不扩大 MCP 权限，也不新增
Agent 确认入口；未来实现复用现有本人修改/审核能力与乐观锁。

对已知来源支持链建立只读 impact projection：输入 source/record/revision，输出依赖的
可信上下文、主题文档版本、翻译、提炼预览及客户端缓存标识。原件与派生记录之间的未知链接
标为未覆盖，不能承诺全量依赖图。投影可重建，不作为第二个可编辑事实库。

## 更正后传播与撤回

同一事务校验 owner/scope、revision 与明确确认，追加新版本并排除旧 active；生成治理审计
及可幂等处理的派生内容失效任务。后台显示“判断已更正”与“派生内容已刷新”两个状态。
任务重试只能刷新派生投影，不重复写本人陈述，不调用模型；需要付费重提炼另走预算守卫。

旧文档历史仍可查看但明确带 superseded/stale 标记。当前 context 不返回被撤回版；Agent 在
有意义任务边界重新读取 context_revision，清理旧缓存。跨Agent主动通知/撤回确认尚未实现，
在没有回执前不能声称过去已加载的上下文已经自动消失。

记忆拒绝、隐私撤回与删除原件是不同请求。前两者先停止可信召回/限制访问并留审计；物理
删除原件、COS备份或可恢复副本需另定义授权与保留策略，不以治理 rejected 顺带删除。

## 执行顺序与回滚

1. 只读诊断：未知归属/对象/日期、孤立 supersedes、已失效但仍 active、跨范围链接、缺来源、
   不可定位的派生内容，按错误类别计数；不导出整库正文到公开代码仓库。
2. 固定快照与恢复演练：验证来源/记录/治理/旧版链及权限；生产备份在私有目录/COS。
3. 增量迁移：增加审计结构及索引，旧读写路径继续兼容；旧未知位不回填，仅标记追溯不完整。
4. 合成恢复库验证后，以 feature flag 开新路径；维护版本和撤回事件均幂等、拒绝旧revision。
5. 回滚先关闭新读写路径，不删除审计事件、不复活已撤回判断；只有可恢复副本演练证明一致
   才安排生产变更。业务回滚与恢复整个数据库不同，后者可能丢失变更后已确认资料。

## 必须验收

- 同一人纠正：两个Agent新请求得到同一新版本；旧版仍可查，旧缓存不得继续称当前事实。
- 不同人观点：文本相反也不互相取代，匿名讲话者不被合并成本人。
- 条件与时间：历史改变/系统纠错分别测试，未来成立与当天失效不得进入当前可信上下文。
- 未知时间：保存未知，不用 reviewed/created 补齐；追溯缺口显式显示。
- 并发与失败：stale record/governance revision 拒绝；派生刷新中断可补偿，来源和旧链不丢。
- 撤回影响：当前可信结果立即排除，文档/翻译/预览分别标记刷新结果，未覆盖依赖明确列出。

设计完成替代语义验收。本文不证明现有历史内容可信，也未改变处理队列或模型预算。
