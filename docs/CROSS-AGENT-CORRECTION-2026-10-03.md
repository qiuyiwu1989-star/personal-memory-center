# 跨 Agent 纠正闭环验收（2026-10-03）

本轮使用临时 SQLite、明确标记的合成陈述和两份不同的只读 MCP 凭据，验证同一记忆范围里的纠正能在下一次读取时被两个 Agent 同时看见。没有接触生产数据、创建真实凭据、调用模型或变更权限与数据库结构。

## 验证链路

本人 REST 创建并明确确认 A → Alpha / Beta 通过真实 `tools/call memory_context` 读取 A → 本人修订为 B（候选）→ 两个读取端均返回空可信上下文 → 本人明确审核 B → 两个读取端读取 B → 本人撤回 B → 两个读取端再次返回空可信上下文。

这条链路要求：

- 新修订在重新确认前不能继承旧版本的可信状态。
- 撤回或失效后不能回退到已被取代的 A。
- `revision`、来源 `source_id/message_id` 和历史治理状态可以回查。
- `context_revision` 随可信内容变化而变化；相同参数与内容在不同读取凭据下保持相同标记。
- 历史原文仍保留，但不会因为保留在档案中就再次进入可信上下文。

`tests/test_memory_cross_agent_correction.py` 包含三个协议层验收：

| 场景 | 验证结果 |
| --- | --- |
| 修订 → 候选 → 明确审核 → 撤回 | 双读取端同步变化，旧版本 superseded；两个来源正文均保留 |
| 到达 `valid_until` 当日 | 有效期为右侧开放区间；双读取端排除已失效 B，也不复活 A |
| 缩减 Alpha 的范围，再撤销其凭据 | 下一请求分别产生工具权限错误和 HTTP 401，不返回旧内容；Beta 不受影响 |

有效期测试仅在读取时模拟时钟到期，未直接改写数据库，也没有通过真假词汇、关键词匹配来判定语义质量。所有陈述都是测试合成内容；这里验证的是显式审核、修订、时间与权限行为，不是事实正确率。

## 验证与限制

本轮目标测试：3 项通过。公开树扫描另行执行并记录于本轮总报告。真实 REST 创建/修订/审核路由和 MCP HTTP `tools/call` 均经过 Starlette TestClient；worker 关闭，模型调用次数保持 0。

这不等于 ArkClaw 或 LocalVault 实例联调已经完成，也不验证外部客户端会主动丢弃先前缓存的内容。服务端只能保证下一次请求采用当前权限与可信状态。客户端应在重要行动前重新读取，并按 `context_revision` 更新本地上下文；旧上下文已被客户端保存时，撤销权限无法远程删除那份副本。

测试没有覆盖并发修订、外部模型生成语义质量或生产 PostgreSQL 的整体性能，这些由既有专项测试和发布恢复验收分别负责。本轮没有新增自动确认机制。
