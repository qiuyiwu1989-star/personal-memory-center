# 记忆中心全景与下一阶段路线 · 2026-10-04

## 总体结论与证据口径

目标仍是：让本人和未来 Agent 在需要时取得有出处、知道是谁的观点、仍然有效、可以纠正的上下文。

现在已经形成归档、后台管理、候选治理和 MCP 读取的首版基础设施。尚未证明自动提炼可以稳定地产出可信个人记忆，也没有完成真实 ArkClaw、LocalVault 与已登录生产后台的全链路验收。因此不能用开发测试通过率代表记忆质量，不能用归档数量代表个人记忆数量。

本报告依据截至 2026-10-04 第三轮执行收据和代码报告；本轮没有重新查询生产数据库，没有模型提炼、预算变更或部署。线上最近核验为 2,228 条记录、personal 范围为 0，MCP 10 个工具，历史批次 paused_budget。公共代码包含实验 v21；生产后端仍是稳定 v17 加撤回补丁。最新 Python 检查为 469 通过、1 项已知预期失败；14 项 Node 通过。

## 一、现有架构

### 1. 原件与来源

Claude 导出已经归档；文档、会议和 Agent 素材采用共同来源规范。原件保存在私有 COS；数据库保存来源索引、文本位置、消息角色、版本和任务状态。系统盘承担应用代码、运行环境、临时文件与必要缓存，不作为唯一原件仓库。私人配置与备份在公开代码仓库之外。

上传者、发言者、观点持有者、讨论对象是不同字段。你上传一份会议记录，不意味着其中每句话都是你的观点。旧摘要可作为来源材料，但不直接视为当前事实。

### 2. 两条处理路径

原件归档后，一条路径建立原文检索索引，不调用 LLM；另一条经预算队列调用 LLM 提出候选。即使没有形成长期记忆，原件仍可以作为明确标注的历史档案检索。

候选需要判断：谁认为、关于谁、什么陈述、何时成立、依据在哪；再核实项目范围、否定与条件、长期价值、冲突和有效时间。引用匹配仅证明引用存在，不证明概括成立。

### 3. 治理与存储

Postgres 是受治理记录的主存储，保留候选、人工复核、修订、撤回和替代关系。重要更正保留旧版本，不能静默覆盖，也不能自动把替代候选确认为新事实。

主题 MD 是阅读、版本比较和导出的派生视图；它不是独立的第二套事实数据库。直接编辑 MD 后自动回写治理账本的完整闭环尚未完成。

### 4. 后台工作台

记忆中心是个人网站后台的独立模块，沿用现有样式。已有主题文档、记忆管理、资料提交、处理任务、原始资料页面，以及人工新增、修改、复核和撤回的代码能力。重提炼有比较流程，方法版本和错误可见。

本地人工治理已有合成验收；生产仅验证了登录保护和服务状态，尚不能把已登录的真实操作体验写成验收完成。

### 5. Agent 接口

MCP 提供统一工具；Skill 约定使用方式；服务端执行范围、动作和预算约束。读取采用渐进加载：任务不需要背景时不读取；需要时先取少量可信背景，再按任务检索，最后查看精确原文或分页文档。候选、原文和可信上下文分开标注。

MCP 检索本身不调用 LLM；Agent 阅读返回内容和生成回答仍消耗其模型 tokens。内部候选证据包接近全量读取的问题尚待优化，返回短不等于服务端成本低。

第三方写入拟采用独立收件范围，例如 agent:arkclaw-inbox，标明 assistant 与 candidate，不能直接写入已确认个人范围。历史只读授权、个人只读授权、收件箱写授权应分别管理；真实实例接入尚未验收。

## 二、完成与未完成

### 已上线或已验证的基础

- 独立公开代码仓库、私有数据隔离、网站后台模块、COS/数据库基础。
- 原件归档、可追溯索引、幂等接收、预算与任务状态、确定性索引更新。
- 受权限约束的 MCP、分层读取、主题 MD 分页/下载/版本比较。
- 人工治理和重提炼比较的实现；撤回保护经过专项验证。
- 主站部署与记忆模块隔离已合并，并在一次真实主站发布中验证不覆盖记忆服务。

### 已开发、尚未接入或尚未充分验收

- 实验 v21 方法、条件范围诊断、来源完整复核包、逐项候选隔离诊断。
- 长来源无损分段规划器及独立覆盖校验：开发组 6 案例、8 单元、75,101 字符分为 11 段；未接生产 worker，未经过真实模型提炼。
- 评测清单、检索实验、合成接入自检及发布对照。预留材料独立性尚未核实，不能称为盲测。
- 时间审计与部分治理迁移的实现、测试，不等于全部生产能力已经启用。

### 尚未完成的核心结果

- 普通不同项目的条件范围问题仍有已知预期失败；诊断标签没有替代语义修复。
- 真正覆盖完整材料的提炼质量、独立评测与低风险自动准入规则。
- 一小组确实有用的可信 personal 上下文；目前为空。
- 生产已登录后台操作，ArkClaw 实例侧读取，LocalVault 实际版本/角色/续传对接。
- 真实任务的回答效果、出处、纠正一致性和端到端 token/延迟成本评测。
- 完整冲突与实体歧义处理、时间查询、跨原件/数据库/MD/索引/缓存的删除传播。
- 经验与任务结果转化为可复用规则的闭环；原子库统一来源映射。

历史批次仍暂停。旧候选不能通过换名称或翻译批量变成已确认记忆。

## 三、研究学习与取舍

| 来源 | 已吸收的原则 | 当前没有采用或没有完成 |
|---|---|---|
| Claude 导出及记忆组织 | 短概览、人物/项目/领域等主题、历史回查、分层加载 | 不假定知道 Claude 私有内部算法；不沿用旧摘要作为本人当前判断 |
| Letta / MemGPT | 少量常用上下文，其余按需读取；控制加载预算 | 不引入完整常驻 Agent 运行时；真实任务收益仍待验证 |
| Graphiti / Zep | 原始事件、事实来源、成立/失效时间、保留历史 | 不整体部署知识图谱；完整双时间查询和关系推理未完成 |
| Mem0 | 抽取、合并、更新、检索拆开；持续候选治理 | 不仅凭相似度自动合并人物、删除旧事实或确认观点 |
| LangMem | 事实、经历、做事规则分层 | 当前偏重来源和事实；经历—结果—规则学习尚未完成 |
| Cognee / GraphRAG | 知识加工与个人记忆区分，派生内容有出处和依赖 | 图谱、全局主题总结、重型语义流水线未部署；原子库继续作为知识素材 |
| LoCoMo / LongMemEval / HaluMem 等评测思路 | 分开评测写入、更新、读取、回答、拒答与成本 | 尚无可信独立评测和多路线真实任务对照；外部成绩不能当作我们的成绩 |

研究学习不等于安装产品，也不等于复现其全部能力。我们已经吸收的主要是“如何组织可信上下文和限制加载”，尚未完成的是“可靠自动更新、经验学习和真实使用收益”。

## 四、边界与原因

1. 原件、候选、可信记忆分层：避免助手发言、临时指令、设想与旧状态混成你的当前判断。没有个人记忆时如实返回空，不拿历史候选补位。
2. 知识与个人记忆共用来源规范、分别治理：原子库适合内容挖掘；个人记忆需要明确归属与时效。“159 条判断”尚无可靠核对，不整体迁移为可信事实。
3. 自动化处理，风险分级准入：归档、分段、索引、调度和审计可自动化；语义提炼使用模型。高影响身份、授权、关系及矛盾更正需要更强证据或明确复核。低风险自动准入规则仍待制定，不要求未来每句话都人工确认。
4. 第三方最小权限：能读不代表能写，能写收件箱不代表能确认个人记忆。权限由服务端控制，来源材料不能授予权限。
5. 渐进检索、按需模型：先用已有 Postgres/COS/MCP/Skill，不建立持续反思的重型管家或全库常驻上下文。向量/图谱只有在实际评测显示必要时再加。
6. 纠正与遗忘可追溯：更正后旧结论不再作为当前事实；期限到达不证明计划已经完成。删除传播尚不完整，不能承诺所有副本已经永久删除。
7. 原文与中文展示分开：中文摘要可以改善使用体验；原始引用、名字、时间和版本保留。翻译不能顺便改变观点归属和确定程度。

## 五、后续执行顺序

| 优先级/阶段 | 工作 | 完成标准 | 模型用量 |
|---|---|---|---|
| P0-A 先修质量与覆盖 | 接入长文分段、角色/原件导航、覆盖与未处理范围；修复条件/项目归属；固定方法版本 | 长文没有静默遗漏；愿望不变决定、条件不被解除、第三方不变本人；独立复核通过 | 工程不用；开发材料提炼与评分需要 |
| P0-B 同步完成治理验收 | 在已登录后台验证补充/修改/撤回/替代；准备少量有来源的个人上下文 | 更正后两份读取凭据读到新状态，旧版可查；personal 不依赖历史候选冒充 | 人工操作不用；可选提炼需要 |
| P1-C 首个真实 Agent | ArkClaw 先只读 personal；再单独验证隔离收件箱；LocalVault 校准作者/时间/版本/幂等/续传 | 真实实例可读出处与版本，重复提交不重复，素材不直接确认，权限越界被拒绝 | 接口不用；客户端推理需要 |
| P1-D 检索与成本 | 对比无记忆、原文检索、治理上下文；优化内部候选扫描；检验不同加载预算 | 有用性、归属、时效、纠正一致性及全链路费用都可量化；保留拒答能力 | 数据筛选不用；回答对照需要 |
| P2-E Claude 分批重治理 | 按方法变更影响与价值选来源，先小试批；只在质量通过后扩大 | 每批有方法、来源覆盖、费用、复核与停止原因；旧候选不自动升格 | 重提炼需要 |
| P2-F 多源持续使用 | 文档/会议统一入口，原子库来源桥接；补删除传播、备份恢复、经验与规则版本 | 所有来源遵守同一治理规范，可更正、可追溯、可限制权限 | 接收不用；转录/语义加工视任务需要 |

P0-A 与 P0-B 可以并行准备；提炼评测依赖覆盖与方法修复，真实回答评测依赖可信个人上下文。接入协议准备不必等全量历史处理完，真实实例验收仍需要运行侧条件。模型用量按运行账本核对；用户此前允许质量确认后增加预算，不意味着当前共享预算可以直接放开。

下一次交付应包含：固定方法与完整来源覆盖结果、开发材料的真实提炼及独立评分、后台人工治理回执、第一批个人上下文及 ArkClaw 实例侧只读结果。达到这些结果，再决定恢复多少历史数据，而不是先把 2,228 条都认作记忆。
