# 记忆中心协作闭环执行计划 · 2026-10-05

目标：其他 Agent 能受限接入，主人能追查结果，更正或撤回后旧结论不继续被当作当前记忆。代码完成、本地协议通过、外部客户端验收、生产上线分别记录。

## 本轮并行分工

| 优先级 | 工作包 | 负责人 | 产物与验收 |
|---|---|---|---|
| P0 | 来源级撤回 | source_withdrawal | 鉴权、幂等、保留历史、派生结果失效与影响回执；独立有效证据不能被误删 |
| P0 | 双向治理账本 | source_ledger | 有界只读 API：来源关联任务/记录/文档、治理状态、实际方法与费用覆盖；反向查证据 |
| P0 | MCP 契约与协议验收 | integration_acceptance | 本地合成服务真实初始化与工具调用；归档、状态、去重、越权、付费拒绝的可重复脚本 |
| P0 | 工作台接入与集成 | 主 Agent | 资料和记忆入口打开治理账本；输入输出安全、范围切换防串页；合并回归 |

子任务共用同一工作区，按文件划分修改范围。撤回负责 core/service，账本负责 web 新只读路由，主 Agent 负责 assets UI；共用依赖改动先协调。所有测试资料为合成，不处理真实历史、不调用模型、不提高预算。

## 完成顺序和放行条件

1. 冻结实际 API 契约，确认当前代码能做到什么。
2. 并行完成后端与协议验收，主 Agent 接工作台。
3. 集成测试、公开树扫描、差异检查；生成完成报告和未通过项。
4. 通过后再准备生产部署包。生产变更与历史批处理分开；本轮不默认把开发 HEAD 覆盖稳定版本。
5. LocalVault / ArkClaw 实际环境联调需要对方运行凭据隔离的自测脚本；本地测试不冒充第三方验收。

## 后续依赖队列

- P1 个人可用记忆质量：来源和撤回闭环完成后，用真实问题评测归属、时间、证据与遗漏；先冻结样本和评分标准，付费处理另计预算。
- P1 渐进式 Skill：采用本轮实际返回结构，明确空结果、冲突、失效和引用策略；不自动回退候选为事实。
- P2 自动治理与多源扩展：真实试点评测通过后，再逐步接会议、文档及原子库，复用同一来源契约。

## 完成边界

来源撤回是可检索性和派生结果有效性的治理操作，不默认物理删除原件。无法撤回已经发送给外部模型的历史提示词。自动判断质量、真实客户端联调、生产发布和全量 Claude 提炼不能用本轮代码测试替代。
