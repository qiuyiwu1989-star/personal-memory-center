# v14：混合证据与模态

方法版本为 `2026-10-01.14`。本轮增加无模型的证据边界与模态检查；仅补充简短的接口提示，不继续用历史失败题反复扩写提示。本次公开测试全部为独立合成材料。

## 证据边界

`prepare_request(source_type, messages, version=...)` 在 v14 下保守划分原子证据。仅在标点外部、后续有明确独立主体时分段。逗号仅允许后续出现明确的“我/我们 + 意愿”开头；普通并列约束不切。条件、列表和带冒号的多行配置保留上下文；省略主语、依赖前文代词及引号内的标点不切。长片段继续使用既有 1000 字符有界分块，因此超长复杂语法仍需要人工或语义质量检查。

原文仍完整归档。证据保留原始 `start`、`end` 和精确引用，未对引用改写或截去否定。保守边界不保证每个片段都只有一个事实，模型仍需按一个独立陈述提出候选。

## 服务附加字段

`resolve_plan(..., version='2026-10-01.14')` 附加 `modality`，模型同名字段被覆盖：

| 值 | 证据文本信号 |
|---|---|
| `stated` | 未检测到下列模态信号，不能据此视为事实已核实 |
| `wish` | 显式希望、想要、考虑等 |
| `plan` | 显式计划、打算等 |
| `conditional` | 显式条件或前提 |
| `mixed` | 意愿/计划与显式决定或完成并存 |

这是证据层的保守标签，并非事实类型或当前有效性。命名事实和后续希望能够独立分段时，各自引用自己的证据。无法安全分段时，不因整段包含希望就拒绝命名事实；下游应结合陈述和证据判断。

后置检查拒绝明显的纯意愿/计划到已完成、已决定或 `decision`/`event` 的升格；条件性意愿或计划不能明显省略条件；否定意愿不能直接改成同动词的肯定意愿。未命中规则不代表蕴含正确，多事实混合、近义改写及复杂否定仍需语义评测。

v13 resolver 的精确来源标题和消息日期附加规则保持；v14 使用同样标签，摘要不把更新时间当作事件时间。无版本或旧版本调用不启用新原子划分及新模态检查。

## 接入与验证

Core 已接入 v14，并在读取候选时从持久化的逐字证据确定性计算 `modality`，不新增独立存储或回填。该标签表示当前规则检测到的文本信号；旧记录不会因此获得核实状态。错误仍经 `ModelOutputError` 保留已测用量。

合成测试验证命名事实与希望分离、精确偏移、列表与条件保留、源标题/日期兼容、明显升格及否定检查、模型伪造标签被覆盖。模拟 HTTP 测试验证新方法实际传入 provider；全部不访问真实模型，不代表真实提炼质量已经通过。
