# 第五轮：v18 生成规则与覆盖收据

本轮三路 Agent 分别完善生成规则、预先冻结独立合成控制、补齐覆盖审阅规范，主 Agent 合并验证并执行有界模型试验。v18 已完成开发，但试验仍未达到放行标准；线上继续保留 v17，全量提炼保持暂停。

## 已完成的开发

- **生成方法 v18**：逐用户消息扫描长期项目边界，包括没有配置优先级提示的普通证据；区分临时写作要求与长期约束；要求混合期望、计划与约束原子拆分，正文与 kind 一致。JSON 示例默认 kind=claim。方法提交为 `5c03fb784ea213757810fc012df320dc8202b219`。
- **既有保护完整继承**：v18 注册到输入切片、条件范围、可见性、解析守卫、历史日期／对话标题包装、摘要时间和核心校验。没有放宽守卫、提高候选上限或新增自动采纳。
- **可选 coverage-v2 审阅收据**：显式来源目标清单、合法 kind、生成／交付两个阶段映射；缺评保留 not_run，未知目标和候选引用拒绝。必需目标遗漏、存疑和未评阻断 ready。未执行生成不能被评分为遗漏或成功；生成完成但交付拒绝分别保留。旧 v1 行为兼容，始终 quality_approved=false。

覆盖工具只验证记录完整性。它不判断来源目标是否正确、不认证评审身份或独立性、不自动确认记忆，也不运行模型。具体格式见 [覆盖与承诺审阅标准](EXTRACTION-COVERAGE-RUBRIC-V1.md)。

## 独立复核与拒绝诊断

来源先行的 v1 rubric 暂定原始生成案例 101、102 通过，103 未运行。该 rubric 允许多个相关目标由一条陈述覆盖；完整来源覆盖不等于每条候选符合生成方法的原子性与单片段合同。

因此追加方法合同专项复核，保留 v1 原件和标签，明确标注这是看过输出后的追加检查：

1. 101 第一条合并了“保留审核记录”和“禁止覆盖已发布版本”两个可独立变更的约束；覆盖完整，但不符合每条一个独立约束的合同。
2. 102 第二条补入选中证据片段没有的项目名称，依赖前一消息。归属正确也不能替代单片段独立支撑要求。
3. 其余三条专项合同检查暂定通过；103 仍未运行。专项聚合为 failed 2、not_run 1，不能作为新盲测成绩。

另一路离线诊断对 102 三条候选逐条重放：第 1、3 条解析和核心校验通过；第 2 条在条件守卫拒绝，未进入核心校验。最窄对照确认了一个词法作用范围误伤：后半段外部测试的预算条件，被当作前半段独立功能期望的条件。删除候选里跨片段补入的项目名后，忠实期望仍被拒绝；移除后半条件提议后，同一期望通过。

这说明条件作用范围处理需要改进，也说明原候选自身仍有证据合同问题。两项问题分别留痕，没有通过放宽守卫把原候选改判有效。本轮未证明 v18 在真实 Claude 数据上的质量改善，没有重新评测旧编号 6–8 或把旧失败改判通过。

## 下一步顺序

**P0 条件作用范围**：先用完全合成的独立期望／后续条件计划及确实受共同条件约束的反例，限定可证明安全的证据切片策略。相邻句、新对象或“另外”都不能独自证明条件独立，不能仅删除条件守卫。

**P0 原子性和单片段支撑**：把这两项与全文覆盖同时纳入生成前冻结 rubric；显式记录未能安全拆分的目标，不靠跨片段补名或合并陈述掩盖。覆盖收据 v2 用于检查审阅记录完整性，语义仍需独立复核。

**P1 固定方法复测**：修改后先跑合成反例，再将旧真实失败样本用作开发回归，另保留未参与调参的真实来源。生成、交付、语义、覆盖分别报告；未运行不计成功。通过这些门槛后再考虑全量整理及实际客户端联调。

`quality_approved=false`、`bulk_resumed=false`。合成控制与 Agent 暂定标签不是人工 gold，也不能代表全库准确率。审阅脚本没有新增后台 API 调用；本轮真实生成用量和子 Agent 推理用量应分别理解。
