# lexical-v3：按语法分段的实验检索

本策略先基于公开合成例子冻结，再交给主任务使用私有评测集。开发者没有读取私有真实 query 或 labels；本文件不报告真实记忆的质量。

## 要解决的问题

v1 用共享汉字匹配，容易把无关记忆召回。v2 要求完整词串或至少两个不同二字片段，能减噪，但自然语言中的二字关键词会被长句包裹，例如合成查询「请问仓库的预算是什么呢？」与合成记录「预算为十元」。v3 用中文语法边界提出额外查询片段，而不使用项目词典、LLM、向量或推断的同义词。

## 冻结规则

1. 保留 v2 的 NFKC、英文小写、英文词边界、问句包装去除和原完整中文词串。
2. 额外去掉固定查询包装：能不能、有没有、请帮忙、帮我、查一下、查找、查询、检索、看看、哪些、一下。
3. 中文词串额外按固定语法边界分段：以及、或者、并且、关于、有关、对于、中的、之中、的、与、和。保留原完整词串，防止含这些字的人名、项目名被完全破坏。
4. 新增片段必须至少两个汉字；单个共享汉字不构成召回。未分段的长串仍要求完整匹配或两个不同二字片段。单汉字查询只允许精确 subject/subject_id。
5. 召回门槛只能由 statement、display_statement、subject、subject_id、source_title/证据对话标题打开；scope、topic 仅辅助计分。quote 不索引。
6. 计分沿用 v2 的字段权重：实体 6、陈述/译文 4、标题 3、范围 1.5、主题 1。每个词或片段取最强字段，完整词串另加奖励；重复出现或中英相同陈述不叠加。
7. 稳定排序，空查询保留原顺序，输入对象不变。无匹配返回空集，不自动退回 v1。

## 接口和边界

- `rank_records_v3(rows, query)`：实验排序。
- `score_record_v3(row, query)`：与实验排序一致的分数。
- `search_records(..., mode='lexical-v3')`：显式选择；默认仍为 `lexical-v1`，`RETRIEVAL_VERSION` 保持 `lexical-v2` 兼容。
- helper 只接收已经 owner/scope 过滤的行；不负责授权、有效期或 candidate/verified 状态判断。上层必须继续实施这些守卫。

## 已知限制和验收

这是语法启发式，不是中文语义理解。它可能把包含「的/与/和」的普通词拆开，虽然原完整串仍在；一条二字片段也可能很泛。缺少语法边界、同义表述、中英跨语查询仍可能漏召回。标题命中不证明事实正确、归属正确或仍然有效。

13 个显式合成测试覆盖二字关键词召回、共享单字拒绝、长词门槛、实体和标题权重、低权重字段守卫、英文词边界、不索引引用、重复去重、空查询、稳定排序、无变异以及保持默认 v1。

真实评测必须与 v1/v2 使用相同封闭语料、相同标注和查询，分别看 P@5、R@5、MRR@5、无目标查询拒答和错误返回数。合成测试通过只证明实现规则，无权据此认定实际质量通过或恢复全量提炼；检索实验不调用提炼模型。
