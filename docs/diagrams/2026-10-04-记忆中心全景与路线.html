总体结论与证据口径

目标仍是：让本人和未来 Agent 在需要时取得有出处、知道是谁的观点、仍然有效、可以纠正的上下文。

现在已经形成归档、后台管理、候选治理和 MCP 读取的首版基础设施。尚未证明自动提炼可以稳定地产出可信个人记忆，也没有完成真实 ArkClaw、LocalVault 与已登录生产后台的全链路验收。因此不能用开发测试通过率代表记忆质量，不能用归档数量代表个人记忆数量。

本报告依据截至 2026-10-04 第三轮执行收据和代码报告；本轮没有重新查询生产数据库，没有模型提炼、预算变更或部署。线上最近核验为 2,228 条记录、personal 范围为 0，MCP 10 个工具，历史批次 paused_budget。公共代码包含实验 v21；生产后端仍是稳定 v17 加撤回补丁。最新 Python 检查为 469 通过、1 项已知预期失败；14 项 Node 通过。

一、现有架构

1. 原件与来源

Claude 导出已经归档；文档、会议和 Agent 素材采用共同来源规范。原件保存在私有 COS；数据库保存来源索引、文本位置、消息角色、版本和任务状态。系统盘承担应用代码、运行环境、临时文件与必要缓存，不作为唯一原件仓库。私人配置与备份在公开代码仓库之外。

上传者、发言者、观点持有者、讨论对象是不同字段。你上传一份会议记录，不意味着其中每句话都是你的观点。旧摘要可作为来源材料，但不直接视为当前事实。

2. 两条处理路径

原件归档后，一条路径建立原文检索索引，不调用 LLM；另一条经预算队列调用 LLM 提出候选。即使没有形成长期记忆，原件仍可以作为明确标注的历史档案检索。

候选需要判断：谁认为、关于谁、什么陈述、何时成立、依据在哪；再核实项目范围、否定与条件、长期价值、冲突和有效时间。引用匹配仅证明引用存在，不证明概括成立。

3. 治理与存储

Postgres 是受治理记录的主存储，保留候选、人工复核、修订、撤回和替代关系。重要更正保留旧版本，不能静默覆盖，也不能自动把替代候选确认为新事实。

主题 MD 是阅读、版本比较和导出的派生视图；它不是独立的第二套事实数据库。直接编辑 MD 后自动回写治理账本的完整闭环尚未完成。

4. 后台工作台

记忆中心是个人网站后台的独立模块，沿用现有样式。已有主题文档、记忆管理、资料提交、处理任务、原始资料页面，以及人工新增、修改、复核和撤回的代码能力。重提炼有比较流程，方法版本和错误可见。

本地人工治理已有合成验收；生产仅验证了登录保护和服务状态，尚不能把已登录的真实操作体验写成验收完成。

5. Agent 接口

MCP 提供统一工具；Skill 约定使用方式；服务端执行范围、动作和预算约束。读取采用渐进加载：任务不需要背景时不读取；需要时先取少量可信背景，再按任务检索，最后查看精确原文或分页文档。候选、原文和可信上下文分开标注。

MCP 检索本身不调用 LLM；Agent 阅读返回内容和生成回答仍消耗其模型 tokens。内部候选证据包接近全量读取的问题尚待优化，返回短不等于服务端成本低。

第三方写入拟采用独立收件范围，例如 agent:arkclaw-inbox，标明 assistant 与 candidate，不能直接写入已确认个人范围。历史只读授权、个人只读授权、收件箱写授权应分别管理；真实实例接入尚未验收。

四、边界与原因

1. 原件、候选、可信记忆分层：避免助手发言、临时指令、设想与旧状态混成你的当前判断。没有个人记忆时如实返回空，不拿历史候选补位。

2. 知识与个人记忆共用来源规范、分别治理：原子库适合内容挖掘；个人记忆需要明确归属与时效。“159 条判断”尚无可靠核对，不整体迁移为可信事实。

3. 自动化处理，风险分级准入：归档、分段、索引、调度和审计可自动化；语义提炼使用模型。高影响身份、授权、关系及矛盾更正需要更强证据或明确复核。低风险自动准入规则仍待制定，不要求未来每句话都人工确认。

4. 第三方最小权限：能读不代表能写，能写收件箱不代表能确认个人记忆。权限由服务端控制，来源材料不能授予权限。

5. 渐进检索、按需模型：先用已有 Postgres/COS/MCP/Skill，不建立持续反思的重型管家或全库常驻上下文。向量/图谱只有在实际评测显示必要时再加。

6. 纠正与遗忘可追溯：更正后旧结论不再作为当前事实；期限到达不证明计划已经完成。删除传播尚不完整，不能承诺所有副本已经永久删除。

7. 原文与中文展示分开：中文摘要可以改善使用体验；原始引用、名字、时间和版本保留。翻译不能顺便改变观点归属和确定程度。
