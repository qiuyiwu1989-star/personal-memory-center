开发建议 · 2026-10-05 · 双向同步尚待开发

LocalVault 与记忆中心：独立运行、统一规范

本地节点处理自己的资料与记忆；共享中心协调多源、权限和当前发布版本。共用规则，不要求共用进程，也不重复做同一份提炼。

双方负责什么

LocalVault：本地记忆节点

白名单资料、原件版本、本地检索、可选提炼、候选治理、文件处置判断、同步账本。

离线能用既有资料与记忆；新提炼是否离线取决于模型。文件保留判断不等于认可其正文。

记忆中心：共享协调节点

来源与候选接收、共享实体映射、治理冲突、版本更正、权限内检索与其他 Agent 接入。

中心发布的当前共享版本可供多 Agent 使用；本地私有资料不必全部同步。

共用的记忆处理链

来源版本保留角色与定位 →候选提炼核对证据与条件 →治理与确认过滤状态与时间 →有界检索发现变化后 →更正历史

最小核心：谁认为 · 关于谁 · 什么陈述 · 何时成立 · 依据在哪。未知不猜，引用存在不代表语义正确，归档不等于确认。

程序：归档、分段、去重、同步、状态校验、检索。可选 LLM：候选提炼、语义检查、翻译。本人确认：独立、绑定具体版本的治理事件。

双向同步如何发生

本地 confirmed 不是中心 verified。机器候选保持候选；本人事件需要身份、明确操作、证据版本和预期修订绑定。并发更正保留两项提案，不用最后写入覆盖历史。

开发顺序与验收

  1. P0：可靠来源交付与共同 schema。应用兼容修复，真实小批对账；冻结状态、实体映射和证据格式。
  2. P1：LocalVault 本地记忆。候选库、可选模型与预算、治理 UI、原文回查；工程和真实语义质量分别验收。
  3. P1：中心接收与下行。候选包接收、修订回执、权限内增量日志、冲突处理及原件归档。依赖项通过再接通。
  4. P2：可信本人事件与扩展。设备绑定、身份验证、撤权、防重放；随后自动调度、多格式、多节点。不要先全库提炼。

隔离副本的 14 项 HTTP 检查只证明修复兼容，不证明实际实例已经接入或记忆语义正确。

双方下一份交付

LocalVault

实际版本与入口、记忆 schema 草案、合成来源/运行/事件样例、本地状态与同步账本、原文完整性限制。

记忆中心

字段映射、权限与能力清单、接收/下行协议、质量要求、回执/冲突/撤回语义，以及合成共同 fixtures。
