1. 我们到底在建设什么

项目的稳定定义：让你和未来的 Agent 在需要时，取得有出处、知道是谁的观点、仍然有效的上下文，并且能纠正它。

最初的问题是“Claude 导出的历史资料怎样保存、提炼、迁移”。随着真实数据复核，目标转向了个人长期上下文：你的身份与关系、持续目标、项目决定及理由、反复出现的工作偏好，以及这些判断后来如何改变。网站后台是管理界面，MCP 是跨 Agent 的接口，Skill 是调用策略。

值得保存的长期资产

原始证据、明确归属的判断、有效时间、适用范围、更正历史，以及谁曾经确认了哪个版本。

用户真正需要的结果

少重复交代背景；Agent 不把他人的话当成你的决定；你纠正一次后，下次读取能够使用新状态。

项目经历了四次重要调整

  1. 从导出搬运到来源治理：完整保留原件，同时把正式发言、助手输出、二手摘要和非正文区分。
  2. 从摘要数量到可信程度：2,189 条候选不能直接叫个人记忆，逐字引文校验也不足以证明概括正确。
  3. 从单网页到共享模块：独立公开代码仓库，私有数据留在服务器；网站、人机协作和多个 Agent 共用同一套规则。
  4. 从重型管家到按需流程：程序负责队列、索引和权限；LLM 在需要理解内容时工作；读取保持轻量。

你的原目标包含自动整理。目前可信个人记忆仍需要明确治理，低风险自动准入尚未完成，因此不能宣称自动记忆管家已经全部实现。

2. 当前架构：两条读取路径，一套治理历史

实现与存储

Python 服务、Flask 管理接口及 MCP/HTTP 服务；前端沿用网站 HTML/CSS/JS。生产 PostgreSQL、本地 SQLite，统一 Store/治理模块；COS 存已归档大原件，系统盘放应用、运行配置、临时文件和缓存。

数据库主要承载 sources/jobs/records、record_governance、memory_entities、变化事件、索引队列、配置和预算账本。scope 是权限和处理隔离，不是质量等级。

为什么不是一堆 MD 就够了

MD 易读、可下载、可比较版本；但主体归属、权限、并发更正、原件依赖和多 Agent 一致性需要治理状态。我们选择数据库保存受治理真源，MD 作为主题投影。任意编辑 MD 自动回写治理的完整流程尚未完成。

关系视图来自已有字段；并没有部署全库语义知识图谱。索引不等于 COS 原件全覆盖，当前主要检索已经解析并登记的文本。

预算暂停的含义

10 月 4 日记录：历史批次账本 1,967,655 / 3,000,000 tokens；通用试验账本 344,430 / 344,430。两类账本累计计量及预留 2,312,085。总上限曾获准到 300 万，但通用预算已满、质量尚未放行，不能把总额度差额视为自动可花的钱，也不能按文件体积直接推算剩余费用。

继续暂停旧批次有依据。下一步需要解决上下文与语义问题并设定有限试跑预算，而不是单纯提高额度继续执行旧混合文本计划。

5. 我们真正形成的记忆方法

一条受治理的判断至少回答五个问题：谁认为、关于谁、说了什么、何时成立、依据在哪。再补充项目范围、条件、来源性质和后来如何改变。

应当保留

P0：重要更正、身份校正、授权边界。

P1：持续关系、长期目标、关键决定与理由。

P2：反复有证据支持的偏好和工作方法。

P3：讨论、草稿、旧尝试，主要留在档案层。

不能自动转换

建议不能变决定；计划不能变完成。

上传者不能变所有发言的作者。

文件保存日期不能变事实成立时间。

“保留这份文件”不能变“认可全文”。

三个状态维度要分别理解

任务状态回答“处理到哪一步”；治理状态回答“是否核实/历史/不采纳”；生命周期与来源撤回回答“当前版本是否仍参与使用”。active 不等于 verified。只有明确核实、主体/归属完整、时间有效、来源未撤回的记录，才进入可信 context。

同时保留档案检索价值：一段还没升格为长期记忆的会议，仍可作为历史证据搜索。系统不应因为个人可信范围为空，就把任何历史搜索结果冒充本人当前观点。

7. LocalVault、原子库和其他 Agent 怎么协作

LocalVault：独立的本地证据节点

索引、检索、来源版本、文件处置判断和可靠交付，即使不接中心仍有产品价值。最新建议首轮不新增完整本地记忆引擎、不调用 LLM。

先落实出网目的/载荷检查、兼容修复、ledger 对账。完整本地候选、模型处理、可信本人确认同步是后续产品选项，尚不是你的正式永久取舍。

记忆中心：跨 Agent 的共享上下文

统一来源、候选、归属/实体、有效性、更正和发布。已核实的共享上下文从这里读取，私人本地资料不要求全部入云。

目前有来源导入与查询；候选包、权限内变更日志、双向冲突和 COS 自动上传仍待开发。

原子库：内容与知识素材

文章、会议可同时产生知识素材和个人判断，两者共用来源引用、各自保留用途。“某篇文章提出什么”不等于“我目前相信什么”。

旧“159 条判断”尚无可靠来源核对，不能整体作为 personal。原子库与中心的统一来源桥接尚未完成。

QMemory / 下游 Agent

项目记忆记录开发状态、决策和交接；个人记忆记录跨项目、跨时间的本人上下文。保持项目原有协议，不让两套真源相互覆盖。

Codex、ArkClaw 等通过 MCP 有界读取，通过 Skill 决定何时查；自己的推理与工具使用仍需服从当前任务授权。

出网闸门是规划要求，尚未据此宣称代码已实现。它要覆盖中心正文、COS 原件与云端模型三个目的；正文获准不意味着原件或模型转交也获准。回执成功、来源归档、候选接受、治理确认应分别显示。

8. 这段建设过程最值得反思什么

  1. 工程扩张快于用户价值验证。接口、配置、评测工具和文档持续增加，首批可信个人背景仍没有形成。接下来用真实任务交付验收，减少只以代码数量和测试数量衡量进展。
  2. 规则迭代在局部样本上前进，但输入语境仍不完整。条件、时间、姓名等守卫能拒绝部分错误；它们不是通用语义引擎。对模型没有看到的上下文，继续增加提示也不能弥补。
  3. 拒绝错误与保留价值必须同时评估。大量返回空可能更安全，却仍可能漏掉关键决定。评测必须同时有正确空结果和必须保留的正例，不能用零输出掩盖低召回。
  4. 文档出现状态漂移。README 仍含早期“7 工具”等描述；后续记录为 12 工具。方案、开发默认版本、生产固定制品容易被混读。应维护一份当前状态入口，并保留历史报告的日期与口径。
  5. “双向”一词曾有歧义。来源到记录的双向账本导航已实现，不等于 LocalVault 与中心双向同步；公网客户端库通过，不等于实际宿主安装通过。此后要分别命名验收对象。
  6. 对 LocalVault 的方案曾过度扩张。从上游工具升级独立产品是合理讨论，但完整记忆引擎工作包应先收敛。已接受评审中的阶段划分和出网前置；不能替用户把评审意见变成永久产品决策。
  7. 当前手工治理可能成为新瓶颈。若要求你逐条核实全部历史，自动化目标就未达到。后续应按风险、价值和证据把复核集中到少量高价值/歧义项；自动准入需要单独设计和验证，不能偷偷绕过本人确认。

成本不能只看提炼 tokens

需要同时观察原件解析/转录、LLM 提炼与复核、Agent 读取后回答 tokens、数据库扫描/存储以及人工核实时间。服务端不调用 LLM 的检索依然有计算与上下文成本；1,600 字符预算也不是精确 token 数。当前尚无完整真实任务的收益/成本对照。

9. 下一阶段：先完成一条可用闭环，再扩大

以下是建议验收顺序，不是本轮已执行的任务，不承诺未经吞吐与人力验证的日期。中心质量工作与 LocalVault 可靠交付可以并行准备。

P0-A 固定最新状态与质量试跑合同

负责人：中心。解决 3 个部分上下文请求的用途、角色、更正与邻接条件；固定同一方法、来源版本、模型配置、评分要求和有限预算。形成可审阅试跑包。

验收：缺语境仍明确阻断；不混版本、不把资料日期当成立日期。无新数据库迁移；不自动恢复历史队列。

P0-B 做成第一批有用的个人上下文

负责人：中心 + 本人复核。建议先从已有开发材料和明确决定中准备约 10–20 条高价值候选（建议规模，不是现有完成数），逐项提供来源、范围和不确定性。具体事实确认与开发授权分开。

验收：在后台补充/修改/核实；两个授权读取端看到一致新状态；旧版可追溯，撤回后退出当前读取。先沿用已有表，不全库回填。

P0-C LocalVault 实际小批交付

负责人：LocalVault 负责出网检查与 ledger，中心负责来源契约和回执。先应用真实 HTTP 缺陷修复，再选择 3–5 份已授权资料。实际实例配置、代码版本和报告全部绑定。

验收：长文不丢、角色保留、重复不重复、失败不推进、断网可恢复；正文与原件权限分别核对。中心依赖不能被另一份方案代替。

P1 真实任务与更正对照

相同问题比较无记忆、原文检索、治理上下文三条路径。明确哪些问题应该答、哪些应该说不知道；记录归属、时效、证据、关键遗漏、延迟和总用量。开发集与独立留出组分开。

验收：有用性与关键错误不靠自述，独立评分能够复查。先建最小评测记录；若加入展示反馈需单独设计/迁移，点击不改变事实可信度。

P1 Claude 按价值与方法影响分批重治理

首批选高价值、明确决定/更正或被解析改动影响的来源；保留原件、旧候选、旧计划。质量通过后再扩大，按真实片段和实测成本估算剩余时间。

验收：每批有来源覆盖、方法/配置、费用、质量、未处理项与停止原因。主要是有证据的回填/重规划，不清库、不将全部摘要变长期画像。

P2 多源持续使用与可选自动化

按需求补状态下行、冲突、原子库来源映射、原件授权上传、完整删除传播和经验规则。LocalVault 独立记忆引擎、自动准入、图谱/向量等通过真实收益后再决定。

验收：新协议和新结构分别审查迁移、权限、恢复与成本。当前唯一需要新增结构评审的重点是跨节点事件/变更日志等，不重复建设已有治理表。

七条可由本人核验的检查
  1. 在记忆关系页选一个已登记实体，逐条核对同名不同人未混入；失败定位实体映射（FC-01/08）。
  2. 打开一条当前记忆，能回答谁认为、关于谁、何时成立，并回查实际来源；空值不得当本人或今天（FC-03/04）。
  3. 修改一条合成或已授权记忆，刷新新版本，再查旧版本和更正记录；不能覆盖历史（FC-04）。
  4. 用两个人工写入口提交相同无效日期/未登记实体，均被共享契约拒绝；多个调用点不算多套规则（FC-02）。
  5. 向普通 Agent 收件范围提交“说话人9”候选，允许保留原文但不能直接成为已核实实体判断；注册人物另需明确依据（FC-01/08）。
  6. 查询真实任务展示过的记录 ID 与版本。目前标准展示记录尚未建设，这项不能记为完成。
  7. 若未来加入点赞/采纳，检查其是否只影响展示策略，不改变 verified、来源或有效期；目前无反馈闭环，不能自称越用越聪明（FC-05）。

本人生产操作应选择获授权样本；本清单是验收方法，没有在本轮执行写入。模板中的“硬工程”标签不能代替本项目实际依赖和风险评估。
