多源数据如何成为可靠记忆

不同入口保留各自证据，共用治理、文档组织与任务验收。以 Claude 的组织方式为参照，用实际评测决定能否扩大处理。

质量不是“生成同样多的 MD”

记录层要有依据、归属与时间；文档层要保留目标、决策理由、工作方式和变化。低质量来源留档或待核实，不能靠更强模型承诺同等质量。

七个环节，模型用量分开记

1 · 接收与归档
核权限、原件、哈希、来源键；原始数据完整留存。
通常不用 LLM
2 · 解析与分段
消息/页/标题边界与版本定位；失败留在解析状态。
OCR/转写另计
3 · 提出候选
规则筛选后选择性提炼；允许零记忆，不代表丢数据。
提炼使用 LLM
4 · 治理检查
谁认为、关于谁、语义支持、时间、价值、范围；未知不补造。
程序 + 必要语义辅助
5 · 差异与版本
新增/重复/冲突/取代分开；重跑先比较，旧版可查。
存版本不用 LLM
6 · 小文档投影
保留目标、理由、方法与未决问题；附依赖记录和版本。
投影不用 LLM；整合可能用 LLM
7 · 读取与纠正
按权限、状态和任务召回；纠正影响下一次使用。
记忆侧读取不用 LLM

怎样验收“像 Claude 一样组织、比旧摘要更可靠”

证据与归属

原话支持概括；助手建议、外部观点、用户决定分开；同名人物不强合并。

时间与长期用途

旧计划不当完成，单次要求不当习惯；成立时间未知就标未知。

语境与协作效果

小文档能回答“为什么、怎样做、还有什么未决”；跨 Agent 纠正生效，权限隔离有效。

起步工作量建议：50 条代表陈述、10 个真实任务，每种新增来源补至少 5 个边界样本。这是计划，不是已完成数量或质量保证。先建立基线，再决定扩批门槛。

工作计划：按依赖逐步交付

A · 先做

基线与来源协议

清点新旧数据，建立代表样本和真实问题；核对私有原件、生产访问和备份。

验收：质量有可复查的对照依据。
B · 依赖 A

最小治理与安全重跑

补归属、实体、有效时间、候选状态；记录每次提炼和差异。

验收：未知不猜、旧版不覆盖，隔离迁移通过。
C · 依赖 B

方法与小主题文档

版本化提炼方法，核对样本；保留工作方式、决策理由、来源与变化。

验收：记录层与文档层均在固定样本检查。
D · 依赖 C

首批新来源与 MCP

先 TXT/MD + 一个 Agent，统一预算；短上下文和主题分页。

验收：一条真实导入→读取→纠正链路跑通。
E · 依赖 D

后台与旧数据迁移

固定模块版本接入原后台；显示资料、状态、纠正和重跑差异。

验收：备份回退、第二 Agent 一致性和隔离通过。
F · 依赖 E

有条件扩批与扩格式

依据用量和质量设新预算；PDF、录音、其他系统逐类验收再开放。

验收：新增来源仍通过相同关卡。
Claude 原件和原有文档组织继续保留。预算暂停不自动解除；先审计与小样本核实，再选择性重跑。生产切换、向模型发送材料和恢复批次均是明确操作。
