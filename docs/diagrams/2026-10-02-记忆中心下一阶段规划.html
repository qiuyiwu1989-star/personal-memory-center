人的日常维护

后台统一呈现“资料 → 候选 → 已核实 → 历史/不采纳”。一条记忆可以补充、修订、查看依据和旧版本；待处理事项集中展示。

优先简化现有工作台。高影响身份、人物关系、权限及重要更正保留明确确认；归档、去重、索引和低风险整理自动进行。

Agent 的按需使用

Skill 负责何时检索、怎样引用、何时弃答；MCP 服务负责身份、范围、预算、分页和写入边界。

默认可信上下文为空也可以；原文回查显式标作证据。写入使用单独收件凭据，不能通过材料中的文字扩大权限。

实施顺序与放行条件

阶段做什么验收与依赖
一 · 建立可用个人记忆
现在优先		核查旧原子库及“159 条”来源；建立来源/内容/判断对照。选少量有明确证据的身份校正、关系、长期目标和工作偏好，治理到 personal。每条可追到原文；助手建议不冒充本人；成立时间未知则不推断；项目局部规则不升级为全局偏好。数量由合格证据决定。
二 · 让质量与检索闭环
与阶段一部分并行		先冻结提炼版本，再运行未见会话；对比原文检索、可信记忆、两者结合的回答。检查归属、有效性、引用、弃答及纠正后召回。身份/授权/助手归属等严重错误未解决则继续阻断批量放行。普通错误单独记录；报告样本、模型、实际用量与局限，不能只给总分。
三 · 第三方 Agent 闭环
只读先试；写入后开		ArkClaw 真实实例只读问答验证。补后台 Token 创建/范围/到期/撤销。独立 writer Token + agent:arkclaw-inbox，默认只归档，再审查/提炼。只读零模型调用；越范围、写入、核实拒绝。重试幂等；写入不修改正式记忆；导入成功与索引就绪分开。实例支持两个凭据时配置；不支持则限定一个收件工具或安全代理，禁止合并权限绕过。
四 · 扩大多源自动整理
由前面验收驱动		逐类接会议、文档、其他 Agent 会话；统一来源协议与类型评测。优先处理高价值材料，分批扩量，版本变更允许回查与重提炼。每种来源分别验证角色、引用边界、附件依赖、重复和时间。遵守本轮明确预算；质量达标后再按你的授权调整上限，不自动解除所有成本控制。

控制复杂度与 token 的原则

结构保持轻，治理不能省

继续复用 PostgreSQL：存来源目录、判断、实体 ID、治理状态、版本和任务。COS 保存大文件/原件；系统盘承载程序与临时处理文件。MD 是可读、可下载的主题投影，数据库为当前状态依据；未来若允许编辑 MD，必须通过版本化回写，避免双重真源。

先用稳定实体和明确关系，不急着增加独立图数据库、向量数据库、常驻 LLM 管家。语义检索等复杂度只有在词法检索实际漏召回的评测支持时才增加。

明确哪些步骤花模型用量

无需 LLM：归档、确定性分段、hash 去重、索引、权限、状态更新、本人维护、确定性文档投影与有界检索。

需要模型或人工判断：提炼、观点归属与语义核实、冲突解释、必要的翻译、回答质量评测。读取服务不调用模型，但返回内容仍占调用 Agent 的上下文 tokens。

建议按需读：任务足够明确时不查；缺背景先请求可信上下文，建议 1,600 字符；需要证据再定向搜索，建议 4,000–6,000 字符；原文按 locator 分页。这里是调用建议，实际服务上限由工具校验控制，字符数不等于 token 数。

自动化应该逐层扩大

允许自动接收、归档、分段、索引、提出候选和质量预警。暂时不自动把身份、关系、权限和重要决策升格为已确认判断，也不凭重复出现推断习惯。未来低风险规则可在单独政策与评测通过后放行；本规划没有改变现有候选确认规则。
