# 多源数据进入记忆中枢：质量标准与工作计划

2026-10-01 · 待实施计划。本文不表示新接入器、治理字段或重跑机制已上线，不启动模型或批量任务。配套 [离线流程图](diagrams/2026-10-01-多源记忆接入与工作计划.html)。

## 目标与质量定义

保留 Claude 导出的好组织方式：个人/项目分层、小主题文档、描述与别名、工作方法和决策理由、历史变化。它们是设计参照，不是已经验证的质量分数。

新旧数据共用一套标准：有来源、归属明确、时间不过度推断、有长期用途、保持必要上下文、可以纠正，并在实际任务中被正确召回。任何模型或统一提示词均不能保证不同来源达到完全相同的质量；低质量输入留档或待核实，不通过放宽标准获得“同等质量”。

质量分两层：

- **记录层**：五位结构、证据支持、范围、状态、版本与取代关系。摘要中的“stated”不能替代原话核对。
- **文档层**：围绕人物/项目/主题，保留目标、当前理解、决策及理由、工作方式、未决问题、重要变化与来源。不是把全部记录拼成巨型 MD。

## 多种入口，同一来源协议

| 来源 | 起步接入方式 | 保留的证据定位 | 特有质量检查 |
|---|---|---|---|
| Agent / 对话 | 现有 MCP 小批导入、导出包适配器 | 对话/消息 ID、角色、原始时间 | 助手输出、转述与本人决定分开；角色不等于主张者 |
| TXT / MD / 笔记 | 现有上传入口，补标题/段落定位 | 文件 ID、版本、标题路径、段落 | 草稿或临时指令不推成长期偏好 |
| PDF / PPT / Word | 后续格式解析器 | 私有原件、页/幻灯片/段落、解析版本 | 先验收解析/OCR，无法可靠识别时不提炼 |
| 录音 / 会议 | 先复用已有转写系统，不重复造转写服务 | 原录音引用、片段起止时间、说话人局部 ID | 转写错误、身份未明、引述观点保持不确定 |
| 网页 / 外部资料 | 经授权保存内容快照或可靠原系统引用 | URL、作者、采集时间、内容哈希 | 外部观点进入资料/原子层，不默认是用户立场 |
| 原子库 / 项目系统 | 按稳定 ID 引用；需要才适配 | 原对象 ID、版本和真源 | 任务状态回查真源，派生副本不算新独立证据 |

拟统一 Source Envelope：来源键、来源类型、原件引用、内容哈希、原始时间、入库时间、作者/消息角色、所属人物/项目、原始定位、解析版本、权限与授权范围。owner/scope 从服务端身份取得；内容不能自行扩大授权。

当前消息协议仅支持 id/role/text 及 source_title/created_at，没有完整页码、实体、授权和解析元信息。上述字段需要扩展与校验，不可只写在 Skill 中就声称服务端已保留。

## 标准管线

1. **接收与归档**：权限检查、原件保存、哈希、稳定来源键；先留下完整来源。
2. **解析与分段**：保留标题、会话或页码边界和定位；必要的上下文携带邻接信息。重复片段用共同原始来源去重。
3. **选择性提出候选**：规则先筛选，必要时模型提炼。允许零记忆；未提炼不等于数据丢失。
4. **治理检查**：引用存在、概括受支持、谁认为/关于谁、时间、长期价值、冲突/重复与范围。模型辅助语义检查；程序约束结构与权限；身份与时间不确定时保持未知。
5. **差异与版本提交**：新增、重复、冲突、取代明确区分；重跑结果先比较，旧记录保留。低风险明确陈述自动应用，歧义留下待核实，不自动升格为确认。
6. **小文档投影**：从受控状态和记录生成目录/摘要/子文档，附引用和依赖版本；变更只更新受影响文档。
7. **按任务提供与纠正回流**：MCP 返回短结果；必要时展开原文。纠正创建新版本，影响后续读取与投影。

来源保存与模型提炼要可分开控制。当前 memory_import 接收后会入自动提炼队列，不能当成零成本归档接口。第一阶段应增加归档/提炼策略和预算入口，再允许多源持续输入；普通 MCP 导入不得绕开批次用量管理。

## 质量关卡

| 检查 | 如何验收 | 不通过的去向 |
|---|---|---|
| 原件与来源 | 导入前后哈希/文本保留、定位能回查 | 解析失败/归档错误，不继续提炼 |
| 引用与语义支持 | 程序检查引用；对固定样本逐条核对概括有无越界 | 待核实或驳回候选，原件保留 |
| 主张者与对象 | 样本含助手建议、转述、同名人物和未明说话人 | 不署用户名，不强合实体 |
| 时间与演变 | 样本含旧计划、未完成项目、显式更正和未知日期 | 历史/待核实，不伪造当前状态 |
| 长期价值与上下文 | 区分一次性要求与长期偏好，保留决定的理由 | 档案/内容原子；不是硬删 |
| 文档质量 | 从小文档回答目标、决策理由、工作方式和未决问题，引用对应原文 | 标过时或待修订，不把巨型拼接当通过 |
| 读取与隔离 | 同任务比较无记忆/短上下文/原话展开，另测撤权和跨范围 | 修召回或权限，未通过不扩大接入 |
| 纠正传播 | 一个 Agent 使用后纠正，另一个新会话读取新版并能查旧版 | 修版本/投影/缓存，不继续扩批次 |

工作用固定评测集起步：**计划选 50 条代表陈述、10 个真实任务，再给每种新来源补至少 5 个边界样本**。这些是起步工作量，不是已抽样数量或统计显著性证明。由来源对照、抽样审阅与用户实际纠正形成基准，不让同一模型打分成为唯一依据。

明确身份错配、助手观点冒充本人、伪造完成状态、越权读取列为关键错误；评测发现这些错误先修复并复测。其他质量项报告实际比例与漏项，第一轮建立基线后定扩批标准，不预先宣布“同等质量”或提升百分比。

## 工作包与依赖

| 工作包 | 交付物 | 验收/后续依赖 |
|---|---|---|
| A · 基线与来源协议 | 新旧数据清点、代表样本、10 个任务、统一字段契约；核对生产访问与备份 | 有实际对照依据；私有样本不进公开仓库 |
| B · 最小治理与安全重跑 | 增量字段迁移、必要实体 ID、归属/有效时间、独立候选状态、extraction_runs 和重跑差异 | 不补造未知、不覆盖旧版；隔离库迁移和回放通过 |
| C · 提炼与小文档 | 版本化方法、选择性提炼、语义抽检、人物/项目/主题小 MD、依赖与更新 | 在 A 的固定样本上验收记录层与文档层；预算有上限 |
| D · 首批新来源与轻量 MCP | 先接 TXT/MD 和一个 Agent；来源元信息、统一预算、短任务上下文、分页、Skill | 完成原件→候选→文档→读取→纠正；复杂任务可按需展开 |
| E · 网站接入与旧数据迁移 | 固定独立仓库版本、原后台样式、资料/状态/纠正/重跑差异入口；旧摘要按来源迁移 | 备份和回退验证，第二 Agent 一致性与范围隔离通过 |
| F · 扩批与更多格式 | 有新预算的选择性历史提炼；PDF/录音/其他系统逐类适配 | 每类解析与记忆评测通过后启用，不一次全开 |

依赖为 A → B → C → D → E → F。实现可在隔离环境推进；生产写库/部署、向外部模型发送材料和批次恢复需相应明确授权与可用环境。整个计划不依赖新图数据库、Agent 群或每次读取的 LLM 总结。

## Claude 旧数据怎样并行处理

已有摘要与文件保留原始组织和版本，作为导航与证据查找起点；已有候选分类审计，优先核实身份、更正、关系、关键决策和工作方式。对话补证据、发现遗漏，不先全量推倒重做。

旧预算暂停保持。A 阶段尽量使用本地规则和原文审阅；模型评测需要另行确定样本预算，不默认续用已耗尽额度。B/C 验收后才回填或生成受控的新投影；E 备份与隔离迁移验证后才切换生产；F 根据实测用量决定剩余材料。

## 成本与人的参与

归档、哈希、版本、权限、检索和已有投影读取不需要记忆侧 LLM。OCR/转写取决于外部系统；候选提炼、语义辅助检查、主题整合可能消耗模型 tokens，需分别记录。

相同来源哈希+解析版本+方法版本复用结果；只重建变化的文档。失败无 usage 时记录未知或保守预留，不能当作零费用。模型预算与 Agent 阅读 token 分开统计。

日常上传、整理和读取尽量自动。人只需对关键歧义、少量基准样本和实际错误给反馈，不要求通读全部候选。暂停批次/增加预算/生产切换仍是明确操作。

**立即执行顺序建议：先 A 的真实基线与协议，随后在独立仓库实现 B。** 尚未取得生产访问时，先完成隔离迁移与合成边界测试；本地示范结果不能代替全量生产质量审计。
