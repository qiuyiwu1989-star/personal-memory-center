# 检索首轮诊断：10 个任务，零模型调用

这是对已有 Claude v9 真实难例输出的**隔离回放**，不是生产记忆采用，也不是质量认证。输入与逐项结果保留在私有目录；公开仓库只包含汇总、程序及明确的合成测试。

## 方法

固定十个中文使用场景：写作边界、写作方法、项目配置、写作风格、大纲参考、课程材料、长期偏好、助手建议、人物归属、临时续写。读取已经存在的 10 份材料与已校验输出，在临时 SQLite Store 重建 19 条候选，逐任务调用与正式系统相同的 `snapshot` 及 `governance.context`。候选查询每次最多 5 条，可信上下文每次最多 1,600 个序列化字符。临时数据库结束后删除，没有创建任务、模型调用或正式数据写入。

没有独立的逐条相关性标注，因此不报告 Precision、Recall 或“10/10 质量通过”。查询与目标人工标注应在后续真实使用集补齐；当前难例集主要覆盖写作材料，不能代表全部个人项目。

## 真实输出

- 10 个场景均命中候选，合计 45 次返回（同一候选可重复出现）。
- 45 次返回都具有来源 ID、消息 ID、原文引用和来源日期。这仅证明技术出处完整，不证明语义归属、长期价值或当前成立。
- 10 次可信上下文均为空，返回均为 91 个序列化字符；这符合未核实候选不得进入可信上下文的规则，不能视作实际使用成功。
- 仅写作风格与助手建议两个查询出现完整查询短语，共 3 次；其余八个查询命中依赖局部字词。这是词法搜索较宽的诊断信号，不是其余结果全部错误的证据。
- 调用实际模型次数为 0，新增实际模型 tokens 为 0。程序里的 UTF-8 字节数除以 4 是粗略诊断值，不是模型 tokenizer 的 token 数，也不是计费值。

## 安全行为的合成验收

四项测试覆盖：候选与可信上下文隔离；核实事实的出处与主张者，以及过期、未来日期、拒收过滤；跨 owner/scope 隔离及零任务/零模型尝试；序列化 500/800/1,600 字符预算与取代后过滤。合成核实记录仅为隔离测试 fixture，不是对真实个人材料的批准。

## 下一步

1. 为实际问题建立独立的预期来源和不应召回内容，覆盖检索零命中、跨语言、旧决策与新更正；将相关性评测与候选抽取评测分开。
2. 改进中文词法召回：增加短语、实体和项目范围权重，减少仅共同单字就返回结果。先测现有系统基线，再比较；不因本轮诊断直接引入向量数据库。
3. 明确两个读取入口：候选搜索供治理/回查；可信上下文供 Agent 执行任务。无可信结果时返回“尚未核实”，不能悄悄回退到候选并称为事实。
4. 为候选搜索补整包字符预算。当前 `snapshot(limit=5)` 限制条数，长陈述与原文引用仍可能很大；可信 context 已有整包字符预算。

可复跑命令（私有路径仅用占位符）：

```sh
python scripts/benchmark_memory_retrieval.py --input /private/input.json --results /private/results.json --output /private/new-report.json
python -m unittest discover -s tests -p 'test_memory_retrieval_benchmark.py' -v
```

程序拒绝将私有报告写入公开仓库，独占创建结果文件并设置权限 0600；标准输出只包含汇总。
