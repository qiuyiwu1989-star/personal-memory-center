# 来源与记忆治理账本（2026-10-05）

本轮实现只读 REST 账本，用于后台解释“收到什么、产出什么、为何尚不可用”。不调用模型、不建索引、不刷新主题文档、不写库。合成测试通过不代表外围客户端已完成真实联调。

## 接口

- `GET /api/inside/memory-center/v1/sources/{source_id}/ledger?scope=personal&limit=20&offset=0`
- `GET /api/inside/memory-center/v1/records/{record_id}/ledger?scope=personal&limit=20&offset=0`

调用需要指定范围的 `read` 权限，并同时匹配 owner、scope、对象 ID。账本不返回原文、摘引、导入原始路径、原始供应商错误及模型审核注释；需要查看原文时另走现有来源读取权限。记忆页的陈述及治理元数据沿用普通 `read` 边界。

`limit` 范围 1–100，`offset` 范围 0–10000；每个列表独立应用同一窗口。响应包含：

- `source`：来源 ID、范围、键、类型、摘要、接收时间、消息数、处理策略、可见性声明、当前来源状态。可见性声明不是权限或真实性证明。
- `summary`：全部直接关联记忆数、当前可用数、候选/历史/拒绝数，以及有记忆引用的消息数与源消息数。类别可能交叠，不能简单相加解释总数。
- `records`：直接来源关系、记忆陈述、治理元数据、证据消息 ID/角色/日期、有效性及结构性排除原因。引用覆盖不证明语义正确、无遗漏或长期价值；没有产出不能解释成“无价值”。
- `jobs` / `runs`：初次处理与重跑的状态、方法版本、是否有失败记录，以及白名单模型用量。缺少方法版本显示未知，不冒充当前版本。
- `attempts`：按任务引用精确匹配的模型预算尝试、预留量及记账量；记账量不等于供应商实测用量。不要把 attempts 与 jobs/runs 的同次用量再次相加。
- `documents`：存储主题文档版本中明确包含该源记忆 ID 的关联，不根据标题、关键词或前缀猜关系。
- `pagination`：每段计数及截断标志。文档段是按范围有界扫描历史投影后匹配，因此单页为空不能证明没有关联；`scan_total` 是可扫描投影版本数，不是匹配总数，`coverage=partial` 表明尚未覆盖所有版本。
- 反向查询另含 `focal_record`，即本次查询的记忆与证据关系，即使它不在来源页的当前窗口内。

## 费用与状态解释

`usage.state` 为 `measured`、`unknown` 或明确记录的 `model_skipped`。只显示供应商已记录的非负整数 `prompt_tokens`、`completion_tokens`、`total_tokens`；不根据分项推测供应商总量。没有价格证据时 `monetary_cost`、`currency` 恒为 null。归档任务缺少模型用量记载时为 unknown，不通过“已归档”状态猜测费用为零。

排除原因是根据治理状态、归属结构、有效时间与修订生命周期计算的机械解释，不是模型重新判断。原始错误只返回 `error_present`，详细失败排查继续使用拥有权限的任务管理入口。

## 来源撤回协同

另由来源生命周期模块处理本人授权的撤回：

- `GET /sources/{source_id}/withdrawal-preview?scope=personal&max_chars=6000`
- `POST /sources/{source_id}/withdraw`，正文为 `{ "scope": "personal", "reason": "说明" }`

撤回不是物理删除。账本保留原始引用和治理历史，但将来源标为 withdrawn，当前可用数为零、对应记录标 `source_withdrawn` 并不再解释为可用上下文。撤回可用性要求独立的 009 迁移；本轮代码交付不自动迁移生产库。

## 验证与边界

合成测试覆盖：归档不触发模型与不修改来源、未知费用不显示零、反向来源查询、范围和 owner 隔离、非法分页、精确文档引用及部分覆盖、错误及私密注释不泄漏、来源撤回和重复回执。

仍未完成：外围设备的双向持久提交账本、全量来源语义质量验收、价格计费结算、全部历史投影的无限扫描、模型审核理由的安全摘要。这些缺口不以计数或卡片状态掩盖。
