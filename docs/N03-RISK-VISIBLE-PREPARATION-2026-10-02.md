# N03 补风险来源：可见文字评测准备

针对前8份零候选小集缺少正向项目事实/约束和他人引文，本轮继续从已授权 Claude 原件
自主选择资料，不要求用户另找文件。此项只准备冻结资料，不调用模型、不写生产或改预算。

## 先固定规则，再独立出题

在查看选中正文与设计问题之前，先冻结筛选协议、固定 seed、排除规则和分层配额：
决定/约束词3份、引文/他人话语词3份、后续修订词2份。每份至少2条有已知角色/日期的
可见消息，最多18,000可见字符；同来源不重复进层，按种子哈希排序，原消息顺序保留。

排除旧7份、新8份以及已有开发/提炼/评测输入、50条来源审阅及已执行历史段。
历史 planned/pending 仅视为队列元信息，不错误地将其当已执行内容。私有收据保留逐文件
hash、原会话canonical hash、可见正文hash、原件定位、可见消息在原会话的位置和排除清单。

72份满足词法风险提名规则，从中冻结8份、64条可见消息、41,335可见字符。最大单会话
规范化序列化15,392字符，在现有单批上限内。此集按风险词有意分层且限制篇幅，不代表
全库平均分布；关键词也不是事实标签，引号可能只是标题，“修改”可能只是写作任务。

## 本批不是“完整无附件来源”

8份全部存在未读附件或工具/未知依赖，明确标记为
`visible_text_only_with_unread_attachments_or_unread_dependencies`。只读取原件中可见 text
块，不打开附件、不取工具结果、不推测文件内容。私有选择收据记录未读附件/块计数及
可见消息位置；原消息日期不等于判断成立时间。外层user也不等于内层引文作者或本人批准。

原件和可见文字可独立支持的结论才评测。只显示“某人回复”而实际内容在未读附件的，
保持未知；助手总结附件的陈述不能代替附件独立证据。助手说文件已修改不证明实际成品正确。

**现有方法限制：**冻结版本的 `Model.extract_source` 只把 `prepare_request(messages)` 交给
模型，source_metadata/选择收据的visibility标记不进入模型正文。不能说模型已收到完整
可见性提示。此次保留方法不变，独立评分仍要求不推测未读依赖，并将这一缺口单独报告；
以后是否改输入封装应另冻结版本再对照，不能事后修改本次方法。

## 冻结交付与边界

无答案输入为 `risk-visible-input-v1.json`，结构继续兼容 cases / sample_index / source_type /
messages / source_metadata。20题及逐来源语义要求另存私有0600，在模型执行前冻结；
提炼执行者不读取题目或预期答案。回答规范仍采用 source-answer-v2，未更换既有冻结协议。

有可见的项目目标、创建陈述和限定任务约束，也有用户转述他人及文稿修订。真实有效期
失效/撤回事件、独立确认的多人会议身份仍不足。文稿标注更改不能自动推为现实公司变化，
代写/案例身份未澄清也不能直接建立本人职业事实。这里不公开评分题、原文、来源ID或答案。
