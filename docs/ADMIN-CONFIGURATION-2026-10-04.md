本轮完成可本地验证的首版。新增“系统配置”“记忆关系”两个入口，沿用后台卡片、字体和颜色，不新增图数据库或持续运行的模型 Agent。尚未部署生产；生产仍保留之前的稳定方法与暂停状态。

## 已实现的配置闭环

- **提炼提示**：查看随代码发布的基础提示，保存不可变补充版本，填写验证依据后启用，或重新启用旧版。补充不能移除服务端原文匹配、归属、输出契约与治理检查；实际语义质量仍需评测。
- **模型连接**：管理当前服务商下的模型/接入点、输出上限与配置版本。读取时冻结一次调用所用版本，不修改共享环境。测得用量记录配置版本；切换前要求任务清空、批次暂停。
- **凭据边界**：API key 继续保存在服务端私有环境/model.json；配置版本不接受 key 字段、不返回 key。后台展示配置状态，尚未实现后台更换密钥或新增服务商。模型地址只能与服务端已配置地址完全一致，防止把现有密钥发给新地址。
- **Skill 管理**：显示随代码发布的两份 Skill 及 SHA；可保存命名版本草稿、查看、导出。客户端安装仍为独立动作，服务端不能把文本草稿自动执行为代码。
- **MCP 管理**：显示当前 10 工具与代码契约指纹；有权限时从配置页进入现有 Agent 凭据管理。工具增删依靠代码发布，不通过后台任意运行脚本。客户端实际安装版本回报与兼容性矩阵尚未完成。
- **审计**：owner + scope 隔离，只有 trusted_user 且 read/write 可管理；乐观 revision 防止并发覆盖；启用记录保留 actor、前后版本与说明。启用不自动确认记忆、提高预算、重处理原件或唤醒历史队列。
- **用量**：新增提示按 UTF-8 字节保守增加一般和历史任务预留；未知用量保留预留，实测结果只结算最新尝试，较早未知尝试不作为免费调用。预算控制仍在现有任务页。

配置按记忆范围保存；不是全站共享密钥编辑器。人工填写验收依据不等于系统自动出具语义质量认证。更换方法需要通过真实评测后再扩大历史处理。

新增 `008_system_configuration.sql` 包含三个配置表，SQLite 本地初始化自动创建。生产需要独立迁移与兼容性验证，不能把公开实验 v21 随配置界面一起直接替换稳定 v17。

## 可视化取舍

第一版采用 **检索列表 + 所选记忆关系图 + 原文与时间详情**：

- 按正文/讨论对象检索和治理状态筛选，每页 40 条，接口最多 80 条。
- 选择一条记忆后，展开“来源、关于谁、谁的观点、取代哪个版本”。
- 缺少 holder/subject_id 时不自动补人物关系；已核实但失效的记忆不会显示为当前可用。
- 关系图来自已有字段，不是语义推断的知识图谱；不调用模型，不把整库一次载入。
- 原文回查保持独立 source_read 权限；显示有限证据预览与明确分页范围。

后续补项目/人物入口、变更时间线和来源处理矩阵。只有任务评测证明确实需要多跳关系时，再考虑图数据库或语义关系提炼。
