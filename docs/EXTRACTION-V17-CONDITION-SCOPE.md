# v17：明确独立范围的精确证据片段

方法版本 `2026-10-03.17`，作用域分段规则 `condition-scope-v1`。
这是无模型的局部边界修复及合成验证，不是语义质量放行。

## 变更

v14–v16 只要整段含条件标记就保持整段。v17 对条件段只增加一个非常窄的
独立片段入口：在引号／括号以外的完整句界后，作者明确写出
“我对另一个独立项目 Orion 的要求是：…”这类带具名项目和独立范围的声明，
且剩余片段不再包含条件标记。另一个项目或重复主体本身不够。

原条件片段仍保留，独立片段仍为候选；两个片段均使用原始连续 offset，
不改原文、不拼接、不移除限定词。列表、引述第三方、代词、同对象总结、
普通“另外／总之／需要”等都不触发这个入口。未明确作用域的混合段继续保守处理。

v17 模型提示另说明：直接要求不应自动改成计划、已采用决定、完成或当前事实。
词法守卫仍不是语义蕴含验证器；需要→计划的模糊改写仍可能需要独立审阅。
未新增静默逐条接受：resolve 仍在任何条目失败时拒绝整份方案，保留原失败收据。

## 兼容与验证

- v13 无 modality，v14–v16 原 span 和守卫行为保持不变。
- v17 保留 v16 来源可见性声明，附件核实仍为 false；来源日期不是事实成立时间。
- 新合成测试对照：纯条件与条件提升、独立具名项目、相邻需求、同对象／不同对象、
  引用与第三方、代词依赖、列表、legacy offset、需求与决定强度边界。
- 未使用私人评测 rubric、调用真实模型、重试旧失败、写入候选、升格可信或恢复全量队列。

## 对旧试验的解释

2026-10-03 冻结 case5 仍是条件作用域疑似误报且需要→计划语义未决。
本变更不声称其通过，也不替换旧输出或失败状态。这个保守规则可能无法解除该样本，
它优先避免删除真实条件。其他未运行样本仍未运行；开发用合成对照不算独立 holdout。
下一步应冻结新版本，独立验证正例与负例，再申请有界真实试验，不以本地测试替代提炼质量。

## 集成

`model.PROMPT_VERSION` 为 v17。core 接收／校验版本列表需要包含该版本；
模型请求预算必须由同一个 `prepare_request` 与同一 PROMPT 构造。
没有变更原版本的 span 解释。scope guard 与 permission guard 分开标识，
避免把权限守卫版本误说成通用语义质量版本。
