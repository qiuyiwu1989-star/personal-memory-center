# 抽取覆盖与承诺一致性审阅标准 v1

本标准用于下一轮抽取验收，补充逐条语义审阅的全文遗漏检查。本文只有明确合成示例，没有读取新生成结果，没有真实评分或质量通过结论。原文的每句话不必成为记忆；需要检查的是可长期使用的重要约束是否被正确保留、合理归档或明确留作未决。

## 先冻结来源目标，再看输出

1. 固定可见原件、原件边界和方法版本；记录附件、缺页、工具输出是否实际可见。不可见内容不纳入可测目标。
2. 审阅者只读来源，列出独立的语义单元，标记说话者、历史项目范围、原文定位、承诺层级、条件及时间。每个单元给出 `must_capture`、`archive_only` 或 `ambiguous`，以及长期价值理由。
3. 将来源目标清单及 rubric 单独冻结，记录哈希和冻结顺序，再运行已冻结方法。包含生成输出的 package 随后冻结；这两个时间点不得混称。
4. 逐目标与候选映射，再逐候选核实五维语义。至少分别审阅原始 provider 输出和已交付候选，避免把被守卫拒绝的正确片段计作交付成功。
5. 新发现的来源目标只能写入追加审阅版本，注明看过输出后补充，不能倒改预定分母或称作独立留出测试。

来源目标不得照着模型输出反推。独立 Agent 审阅是暂定标签；人工身份、来源独立性等声明也不等于经认证的审批。所有结果继续保持 `quality_approved=false`，直至另行明确的质量审批。

## 哪些是重要覆盖目标

`must_capture` 应由直接证据支持，通常包括明确更正、持续授权边界、长期限制、明确项目配置、已采用的关键选择及理由，以及具体的未来计划。保留为候选并不表示当下有效或本人已核实。

以下默认 `archive_only`：即时写作要求、一次性检索和比较问题、助手建议、未被本人采用的第三方观点、稿件与模板正文、实现行数等临时细节。长期约束后面附带临时任务，不能使长期约束一并消失；来源中只有临时任务时，零候选合理。

以下标 `ambiguous`：归属不清、条件的作用范围不清、关键上下文不可见、混合模态无法在现有证据片段契约中安全拆分。保守留档可以是合理行为，但不记为覆盖成功；也不靠补造事实消除未决。

审阅全文，不能只审阅模型挑中的引用。长来源被输入切片或最多 6 条候选的上限挤出重要目标，仍需记录遗漏及原因；上限不是忽略遗漏的免责理由。重复重述只映射到已有目标，不扩大分母。若可测目标超过安全交付容量，记为未完整交付并安排分段或重试设计，不在审阅时人工补齐输出。

## 五维审阅如何覆盖这些问题

| 问题 | 现有维度与审阅要求 |
| --- | --- |
| 全文重要约束遗漏 | 案例级 `source_alignment`：逐 `must_capture` 目标列对应候选；重要缺项为 failed，无法判定为 ambiguous |
| kind 与正文一致 | 逐条 `commitment`：同时比较来源、`kind` 和正文；正文写“考虑”，kind=decision 仍为 failed |
| 混合模态原子化 | `commitment` 与 `condition`：独立事实、愿望、条件不得压成一条；不得用统一 kind 掩盖不同承诺 |
| 零候选合理性 | 案例五维仍须完整审阅；全部 archive_only 才可通过，存在 must_capture 为 failed，只有未决目标则 ambiguous |
| 归属与时间 | `speaker`、`time`：提交人不等于观点持有人；来源日期不等于事件日期或现在有效 |

承诺层级依据语义审阅，不以词表打分代替。现有协议包含 identity、preference、relationship、decision、plan、event、claim、suggestion；并非所有陈述都适合 decision/plan 二选一。`kind` 必须解释其含义与证据关系：明确已采用的选择才支持 decision，明确发生的事件才支持 event；计划、愿望和建议不得升格。独立系统要求可按合适类型保存，不可凭“必须”字样推断已经采纳或完成。缺 kind 时不能声称完成了种类一致性审阅。

## 明确合成的验收例

下面所有人物、系统和来源均为虚构开发素材，不是真实个人判断或独立 holdout。

| 编号 | 合成来源 | 预定目标与判断 |
| --- | --- | --- |
| S1 | “甲项目长期要求保存原文和修订历史。另外请画一张图。” | 持续原文保存、修订历史分别为覆盖目标；即时画图留档。只提画图或全部返回零条为遗漏 |
| S2 | “我考虑明年迁移甲系统。” | 历史考虑/计划，非已决定。正文保留“考虑”但 kind=decision 为失败 |
| S3 | “甲系统目前归我管理。我希望明年做一个新界面。” | 持续管理自述与愿望分开；不得用一条 decision 同时承载，也不得把愿望写成已上线 |
| S4 | “如果成本足够低，我会试迁移。无论是否迁移，原文都必须保留。” | 迁移保留条件；原文保留为明确独立约束。普通相邻句不足以证明条件独立，这里由“无论是否”提供证据 |
| S5 | “请把这篇新闻改成短文。” | archive_only；provider 正常完成且无候选，可经过五维审阅判为合理零候选。超时无输出不是合理零候选 |
| S6 | “乙给我的来信写道：我一直偏好晨间工作。” | 乙的观点，不能变成提交人的偏好；没有本人采用证据时不得写入本人的长期记忆 |
| S7 | “上一条我说错了，甲项目不会迁移，只保留原文。” | 更正是重要目标；保留否定及新状态，并标记与旧候选的纠正关系，不能让新旧并列为当前事实 |

S1 多条拆分必须使用各自足够的证据片段；不能从临时画图反推已建长期系统。S3 若安全片段不能拆分，应先留作未决并修复分段方式，不能降低每条证据的独立支撑要求。

## 记录覆盖：不把陈述正确率叫成召回率

对冻结的可测目标记录：`unit_id`、来源定位、`importance`、`expected_disposition`、承诺层级、条件、时间、对应 `claim_ids`、覆盖标签和原因。覆盖标签建议为 `captured`、`omitted`、`ambiguous`、`not_run`。

分别报告“预定目标中的生成覆盖”和“预定目标中的实际交付覆盖”：正确生成但被管线拒绝的目标，前者可计 captured，后者仍是未交付。仅在来源目标经独立完整审阅、映射逐项核实后，才报告该冻结样本的覆盖比例；它不是整个 Claude 数据的召回率，也不衡量最终回答质量。

质量门槛：预定重要目标不得存在已知遗漏，逐条五维与 kind/正文一致性不得 failed、ambiguous 或 not_run，案例零候选和重复检查完整，交付失败单独阻断放行。有限小样本通过只能支持下一轮试验，不能自动授权全量运行、预算增加或候选升格。

## 现有收据的最小兼容使用方案

`scripts/review_memory_semantics.py` 已支持案例级遗漏与合理零候选审阅，但没有强制 `kind`、目标单元或覆盖映射字段，也不会验证上述字段的完整性。现有五维 schema 不允许新增第六个维度；不要向 `dimensions` 添加 `coverage` 或 `kind_consistency`。

本轮无需改脚本。生成 package 时完整保留原始 `kind`、证据与输出阶段；在来源 rubric 独立私有文件保留目标清单。在案例 `source_alignment.rationale` 引用冻结清单的 SHA256 并逐目标给映射结果，在 `commitment.rationale` 明写实际 kind、正文与来源的对照。若另存覆盖侧车，记录其哈希并与 package/receipt 关联，按私有追加收据方式保存。额外字段即使可被接受或计入哈希，也不会被现有工具语义校验，不能因此声称已机器验收。

若需要下一轮增强机器完整性，最小 v2 提案是可选但显式启用的 `coverage_contract`：验证唯一 unit_id、生成/交付阶段、只引用已存在 claim_id、每个必需目标有标签及理由；启用的包要求每条 claim 有合法 kind，缺值保留 not_run 或拒绝结构。保留 v1 的读取/评分行为，v2 单独标版本与工具哈希；只验证记录完整性，仍由审阅者判断长期价值与语义，不修改生产质量 gate。
