# 第二轮：固定开发用例与语义质量门槛分开

本轮完成无模型离线开发验证，没有进行真实语义验收。固定集含 **17 个明确合成探针**，17 个确定性契约检查符合预期；它不表示模型提炼准确率为 100%。`quality_approved=false`，旧 case5 未复测、未判通过，旧批队列不因此恢复。

## 已完成

固定用例在 `tests/fixtures/memory_quality_contract_v1.json`，每条包含原文、人工编写的探针候选、确定性预期及独立语义审阅问题。没有私人原件、真实模型输出或身份资料。

| 边界 | 探针数 | 检查的行为 |
| --- | ---: | --- |
| 本人明确决定 | 3 | 明确决定可以保持；愿望/计划不能增强为已决定或已完成 |
| 第三方建议 | 4 | 说话者归属待核实；第三方建议不能因外层 user 角色而成为本人决定；本人明确采纳另留对照 |
| 条件性承诺 | 3 | 保留条件、遗漏条件、独立具名项目与整段证据的差异 |
| 后续更正 | 2 | 更正陈述和故意保留的旧计划反例，明确暴露词法层未能理解跨消息失效关系 |
| 需要与计划 | 5 | 忠实需要、增强为计划、原文已有计划、否定计划、同主题混合条件总结 |

`extraction_quality.review` 新版本为 `extraction-quality-review-v3`。新增两个有界诊断信号：

- `need_to_plan_review`：原证据提出需要/要求、没有检测到计划或已述事实，而候选写为计划时，提示承诺可能增强。
- `third_party_advice_review`：证据含第三方建议且候选提及用户，没有窄范围的本人明确采纳信号时，提示归属核实。引述、否定或转述中的“我已决定采用”不解除提示。

二者仅追加 `signal_only=true` 的待审说明，既不修改候选、删除条目、自动拒绝整个提炼结果，也不证明语义错误或正确。没有提示的陈述同样不是可信记忆。规则是窄词法提示，不提供一般自然语言归属或指代解析。

```sh
python3 scripts/evaluate_memory_quality_contract.py
python3 -m unittest tests.test_memory_extraction_quality tests.test_memory_quality_contract tests.test_memory_condition_scope -v
```

可用 `--output /私人目录/新文件.json` 保存收据；文件仅新建，权限 0600，不允许写回公开仓库。检查明确区分 `deterministic_contract_passed` 和 `semantic_judgment=not_run`，无法把契约通过转换成语义通过。人为更改预期会产生检查失败，不动态生成新标准。

新增 6 项测试，连同原有质量和 v17 作用域测试共 **21 项通过**。包括输入不变、错误预期确实失败、伪造真实评测/旧 case5 通过状态被拒绝、需求提示对照、引述采纳及更正盲点。

## 没有解决的部分

1. 固定探针由开发者编写，是开发集，不是独立 holdout。没有真实模型生成、抽取召回率、当前问答质量或第三方 Agent 读写联调结果。
2. 混合同主题条件总结探针是明确合成近邻，不是私人 case5 原件；条件守卫可能误报与需要→计划增强可以同时存在。v17 的独立 ASCII 项目分段并未通用解决它，旧 case5 状态仍为 ambiguous / 待审。
3. 更正反例在词法守卫中不被拒绝，报告故意保留这一盲点，不能称旧计划仍成立。关系失效须通过修订链/治理与独立语义审阅完成。
4. 匹配完整引用只证明出处存在；角色、对象、采纳、时间和模态必须分别判断。当前集合不认证所有人物关系或日期。
5. 诊断最多保留每条 6 个信号，避免无限扩展上下文；没有运行生产、模型、队列或令牌额度变更。

## 下一步真实质量验收

冻结当前方法与这些开发边界后，另选未参与开发的正例和负例，独立保存无答案输入与 rubric。实际模型输出保留失败收据，不更改旧编号，不把未运行当作零候选。分别衡量归属、承诺强度、条件、时间/更正与来源完整度，并测试可信上下文中的最终回答。只有这些实际结果能支持质量放行；本轮离线检查不改变放行状态。
