## 漂移来源：发现覆盖机制，历史执行者仍未证实

主站既有部署工作流会调用旧记忆安装器。该安装器重新计算主站镜像的后端内容版本、重指记忆服务指针，并用基础模板整体替换记忆 Nginx 配置；模板不包含后续追加的独立前端路由。因此主站日常发布存在覆盖独立记忆模块的可复现机制。

远端脚本只读核对确认上述两个覆盖动作，但当前主站镜像计算出的内容版本与之前观察到的旧后端版本不同。有限服务日志只能证明启停，不能证明是谁切换指针。相关服务、计时器和受限脚本/cron 扫描没有给出具体历史执行事件。因此不宣称已找到本次历史漂移根因，也不宣称已根治。扫描排除了 releases、data、依赖目录，未读取凭据、会话正文或完整日志；不能当成整个主机的排除性审计。

私有取证文件只保留版本、文件哈希/时间、单位名、动作分类和聚合事件，不进入公开仓库。

## 本地开发：主站与独立记忆部署隔离

私有主站安装器新增 `--site-deploy`（默认）及显式 `--memory-release`：

- 日常主站发布发现已有记忆 `current`，仅探测现有健康端点并退出；不切指针、不安装依赖、不覆盖路由、不重启服务。
- 已存在但损坏的软链接仍受保护；健康检查失败会让步骤失败，不自动覆盖或回滚。
- 首次没有 `current` 且已经完成私有 provisioning 时，保留既有首次安装入口。
- 独立更新可以显式调用 `--memory-release`；该路径仍是旧安装流程，可能覆盖既有路由，不能将它作为新独立仓库的正式发布方式。新记忆模块继续使用经过审核的独立发布流程。
- 主站工作流明确传 `--site-deploy`。不改变主站其他服务步骤。

远端主站的新备份协调器安装代码已原样保留在首次初始化/显式记忆更新路径，合成首次安装也验证三个协调器脚本落入隔离目录。已有独立记忆服务的 `--site-deploy` 会提前退出，因此不会顺带升级 ops 备份协调器；这类更新必须走单独、显式、受审核的 ops 发布。保留保护不能代替备份组件维护，当前未部署 ops 更新。

本地 Bash 语法通过；6 项合成沙箱测试通过，覆盖默认保护、明确主站保护、损坏指针、显式入口、非法参数和首次初始化。测试将全部服务器路径重定向到临时目录，模拟健康端点与 privileged commands，没有生产连接。改动尚未提交或部署，因此生产未来主站发布的覆盖风险尚未解除。

## 离线版本与路由检查

新增 `scripts/check_memory_release.py`，将经过独立核实的固定期望 manifest 与经过脱敏的观测 JSON 比较：

1. 后端版本、前端版本各自核对，不要求两者相同。
2. 运行进程版本与后端指针一致。
3. 指定后端与前端文件 SHA-256 一致；指针一致不代替内容校验。
4. 精确 URI 的有效路由块哈希一致；缺失路由报漂移。
5. 所需 MCP 工具实际存在，健康观测必须为 JSON `true`。

```sh
python3 scripts/check_memory_release.py --expected private-expectation.json --observed private-observation.json
```

期望字段必须齐全：`backend_release`、`frontend_release`、`backend_files`、`frontend_files`、`routes`、`required_tools`。两个 files 字段为相对文件名至 64 位 SHA-256 的映射；routes 为 URI 至精确有效路由块 SHA-256 映射；required_tools 为工具名列表。观测提供对应前五字段，另加 `process_release`、`tools`、`health_ok`。路由观测必须来自有效加载配置，不能只对仓库模板计算哈希；公网资产和 MCP 应分别实际读取后生成观测。

退出码：0 表示提供的观测匹配；1 表示漂移/缺失；2 表示输入无效。结果只输出原因码，不回显输入或密钥；无网络、无模型、无生产写、无自动回滚。**检查器不自行采集线上状态，匹配不证明输入新鲜或真实，输出 `live_collection_verified=false`。** 当前只有合成测试通过，尚未把实时线上观测接成自动闸门。

9 项合成测试通过，包含后端/前端分版本、进程与指针不同、缺失 UI 路由、代码内容漂移、旧工具集、错误健康值、无效期望及 CLI 退出码/不回显输入。
