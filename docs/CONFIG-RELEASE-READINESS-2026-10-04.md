## 真实 PostgreSQL 验证

新增 `scripts/check_configuration_migration_pg.py`。脚本只接受数据库名以 `memory_config_scratch_` 开头、没有 memory_center schema 的空库；DSN 从私有环境读入，不输出。它不创建/删除数据库，不调用模型，由调用方创建、清理一次性数据库。

在服务器独立 scratch 数据库运行稳定兼容制品，已通过：

先审查发现008的 created REAL 与运行时适配器的 DOUBLE PRECISION 不一致：直接 psql 建表会使用 float4，当前 Unix epoch 的精度不足以保存连续配置事件时间。已把008两处 created 改为 DOUBLE PRECISION。先直接 psql 在独立库执行字面迁移，检查两列类型并回滚；脚本也在 Store 初始化之前执行字面008并检查类型，避免初始化掩盖迁移问题。

- 008 配置表重复应用，幂等。
- 两个同时 revision=0 启用请求，一次成功、一次冲突，审计只记录成功操作。
- 后续启用及重新启用旧版本形成三次审计，原草稿不变。
- 第三方 Agent、未授权范围、跨范围版本不能管理或启用。
- 人为中止事务回滚，active revision 恢复。
- 已知用量结算为合成 123 tokens；未知用量保留完整预留并显示一条 unresolved attempt。
- 历史批次合成两次尝试，其中一次崩溃未知、最新一次有计量；保留第一次完整预留，只结算最新一次。
- 删除本轮配置表后重建的 DDL 回滚演练，基础 records/sources/jobs/bulk 表计数不变。

另以只读 pg_dump 建立独立恢复副本，含2,228 records、900 sources；初始化稳定兼容制品、合成独立范围配置启用、撤除新增表后，records/sources/各job状态/bulk批次状态和额度/通用预算/attempt状态与计量保持完全一致。原生产前后也相同。

scratch 数据库、恢复副本、私有dump和服务器临时制品已清理。生产只读前后收据中的制品、各状态计数、额度与用量相同。公开脚本没有真实资料或凭据，运行中的材料均为显式合成数据。

DDL 回滚演练说明能撤销表，不代表应该在已有配置上线后丢弃配置。实际回滚优先回切旧代码、保留新增表；若要删除新增配置表，应另行备份并明确处理版本与审计记录。
