# 0.2 · 可视化治理、重提炼与中文展示

## 本批交付

| 模块 | 行为 |
|---|---|
| 记忆总览 | 当前范围的原始资料、待核实、可用记忆和历史变化；统计来自数据库 |
| 主题文档 | 分类目录 + 最多 25 组陈述的小文档；明确候选/已核实/历史状态，保留原文证据 |
| 核实管理 | 主张者、对象、成立/失效日期、优先级、审核理由；显式登记实体，不合并同名人物 |
| 资料与再次整理 | 归档/提炼分别选择；稳定来源与重跑请求键，重提炼先比较后采用 |
| 重提炼队列 | 可查看、比较、采用候选、放弃或显式重试；旧结果不覆盖，采用不等于核实 |
| 统一新任务预算 | 普通提炼、重提炼、翻译共用范围账本；预留、实际用量、未知用量分开记 |
| 中文层 | 新提炼中文陈述；旧英文可排队翻译和对照采用，原记录及证据不变 |
| MCP/Skill | 7 个工具；短上下文、主题目录/正文及原文分页；可提交预算内重提炼 |

旧 Claude 批次继续使用已有独立批次账本；不会因升级恢复或提高上限。新任务范围预算默认 0。超过 10 万样本预算，后台要求本人记录质量验收依据；该记录是人的验收，不是程序声称模型已达到某个准确率。

读取与既有文档投影不调用 LLM。翻译属于有预算的模型任务，不在每次访问时重复生成。文档按数据和审核版本缓存；纠正、审核、译文或主题范围改变后重建。

## 质量结论与边界

已选私有 50 条生产样本，进行了陈述与引用的初步对照；不是完整的上下文质量评测。已发现一条短“继续”消息被概括为详细项目结论。V2 增加拒绝此类独立证据的规则和回归测试，强化中文、归属、日期与决策理由提示词。旧错误不会被默默覆盖。

新方法的真实模型抽取/翻译准确率、50 条完整上下文复核、10 个真实任务召回，以及多媒体格式接入仍未验收。本批没有发送真实材料到模型、没有新花费、没有宣布质量门槛通过。

字符预算控制模块返回内容，不能等同模型 tokenizer 的精确 token 数。实体层仅支持登记、范围隔离和候选导航，没有自动身份合并。中文翻译可能误读，需对照采用，不增加事实可信度。

## 验证

- 59 项 Python 测试、3 项文件分段测试、前端语法检查。
- 隔离 PostgreSQL：增量建表、预算结算、重提炼审核、治理核实和跨 Agent 更正。
- 浏览器合成数据：主题目录展开、审核保存后统计更新、任务预算面板、深浅主题和无脚本错误。
- 私人来源、模型配置、样本与截图保存在仓库之外；公开树扫描后才推送。

## 发布与回退

先固定模块提交，备份生产 memory_center schema 和三个模块静态文件；在独立临时数据库恢复旧库副本并验收新代码。单独执行 002_governance.sql，再切换服务 release 并发布三个静态文件。不替换宿主 ws-shell、登录或其他页面。

健康、鉴权边界和生产记录/预算聚合检查不通过时，恢复旧 release 与静态文件。增量空表可以保留兼容；不能把上线后新数据通过整库回滚丢掉。归档、已存在的历史记录和模型配置不随代码替换。

## 待办优先级

3. P1：中文译文抽样；按已有材料的真实使用需求逐步组织人物/项目文档，而不是自动给同名人物合并。
