# 第六轮：条件范围与原子拆分开发

本轮继续 P0，三路 Agent 分别实现安全切片、原子生成约束和独立反例验收。新增代码已提交，尚未替换线上提炼方法。普通条件范围仍有未解决目标，实际模型回归也未达到完整质量门槛。

## 开发结果

**v19 安全切片**仅在来源明确声明“期望独立成立”、否认已经批准实施，并在硬句界之后出现自包含的第一人称条件计划时，拆成两个连续原文片段。前置／后置共同条件、代词承接、第三方引述、列表和引语保持整体。保存既有字符 offsets 和原文，原 v17/v18 行为保留，没有取消条件守卫。

这条规则非常窄。上一轮 102 的“只是期望、未批准、无上线日期”仍不能由该规则安全拆开。独立验收冻结的“不同项目的独立期望与后续条件计划”普通正例也未实现，原源码及拆分期望保留为 expected failure，未改成“返回整体即成功”。另加显式声明的成功例验证新能力。

**v19／v20 原子生成规则**要求每个可独立纠正的约束单独成条，允许多个候选引用同一 evidence_id。subject 和正文的人物、项目、组件必须由选中片段支撑；标题仅作历史标签，不提供语义身份。v20 将 JSON 示例直接改成同一证据的两条规则，并保留零候选、最多六条及共享限定的要求。

两版本完整继承来源可见性、历史日期／标题、摘要时间、语气及条件校验；模型用量收据标识实际 `condition-scope-v2-explicit`。方法提交：v19 `54a334b6e0b675e07582708ef032ac515d8e16fb`，v20 `38f19e8bb0b8fd46f2602821ff3a0135baef5db4`。

## 下一个具体任务

先把拆分后的共同限定作为一个整体验收：项目范围、生效起点、持续时间、结束条件、必要前提、否定与持有人都须逐条保留。v20 的首规则漏记来源“从现在起”生效限定；来源消息日期标签不等于事实有效起点，不能靠元数据前缀改判完整。

条件作用范围不明的普通来源继续作为未决目标。下一步需设计带完整上下文、可追溯范围说明的审核路径，避免仅凭新主体、项目名或“另外”释放条件，也避免对已知无法安全判断的来源重复付费重试。完成这些修复后，才安排真实历史开发回归与未参与调参的独立资料；后台体验和客户端联调按先前 P1/P2 计划继续排队。
