# 旧导出与候选怎样处理

## 处理原则

原件保留，旧提炼结果保留来源和方法版本。先检查，再决定分类、取代或重跑。不要清空数据库后把全部原件重新送模型，也不要自动把所有旧候选标为当前事实。

## 实施顺序

1. 建运行库备份，核对来源归档哈希。暂停新增批量提炼；未处理段继续留在队列计划中。
2. 用只读审计清点归属、摘要来源、缺日期和临时任务信号。不改生命周期、不花模型 tokens。
3. 按用户发言、助手发言、二手摘要、明确纠正分层抽样，人工核对“有用 / 临时 / 归属错误 / 概括越界 / 冲突 / 过时”。
4. 增加治理字段与独立候选状态；回填可证明的信息。助手意见与二手摘要单独供探索，默认当前事实检索排除未核实候选。
5. 改进方法后，只重跑抽样原文；记录方法/模型/来源哈希、用量及新增/重复/冲突/取代差异。保持旧结果可追。
6. 同一评测集通过后，按用途选择剩余材料并设新预算；显式决定是否恢复队列。原件已归档，不需要重新上传整批。

## 能力边界

0.1 有原件/来源、批次预算、明确纠正和只读审计。独立治理状态、重跑差异层、模型质量评测及自动迁移尚未实现。审计是迁移准备，**不会执行第 4–6 步**。

外部 Agent 普通小批导入不能代替大包归档与预算调度。模型网络失败而没有 usage 时，用量未知，不推断为免费。
