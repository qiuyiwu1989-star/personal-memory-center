# 候选生成 v13：来源元数据与语义内容分开

本轮先尝试 v11 提示改进，再加入 v12 来源范围附加，最终保留 v13。不同方法结果独立保存，未覆盖旧合同、原文或旧回执。

## 已实现

服务端根据模型选定的 evidence_id 找到原消息，逐字附加来源对话标题及正规化消息日期。来源消息日期显式标为“非事件成立时间，当前有效性待核实”。项目范围是来源对话，不推断项目身份。二手摘要不附更新时间，仍须保留二手归属和“原始时间未知”。

附加标签不改 quote、message_id、原始模型结果或历史记录；只影响 v12/v13 新输出，旧方法兼容。v13 的措辞、即时指令检查仅对正文执行，不能把来源标题里的指令文字当作用户指令；剥离的标签必须与原消息元数据完全一致，正文里的指令仍会被拒绝。

生成提示保持希望、计划、决定、完成的差别，限制单候选一个独立事实，要求跨证据段去掉同义复述、相对时间不补算原文没有的起止年份。上限是上限，不是应当填满的条数。

## 真实验证和剩余问题

固定13材料经历 v11/v12/v13 同合同回归。v13 技术和合同目标均13/13，但仍有1项程度措辞警告。新3份材料技术3/3，合同2/3且有1项警告：混合证据里已有事实与希望角色被合并成确定用途。

这些是局部 Agent 审阅，不是用户确认、独立人工金标准或全库质量保证。没有采用真实候选、更新正式记录、恢复历史全量或批准质量。

下一步应处理原子证据及模态约束，而不是继续针对固定题加提示。拆证据须保留完整归档、字节/字符定位、否定和列表上下文，并对多源新材料验证；不能在拆分时改变谁说了什么或隐含审批。后续尚未实施，不把它算成已修复。

本轮真实模型消费46,290 tokens。固定回归每版9请求4跳过；新批3请求。本轮保守用量限额60,000，所有调用按共享账本预留/结算并关闭额外额度。一次权限故障发生于调用前，确认0尝试后恢复目录权限和关闭未用额度，才执行；没有把失败请求当成免费模型请求。
