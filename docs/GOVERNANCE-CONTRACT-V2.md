# 统一判断治理契约 v2

日期：2026-10-02。范围：现有记忆核心的归属、时间、状态验证与增量建设；不迁移旧原子库，不批量提炼，不自动确认历史候选。本契约不改变现有可信上下文准入，不承诺提炼语义质量或检索收益。

## 一条判断的五个位置

- 谁认为：`record_governance.holder`，明确登记的稳定实体 ID；未知保持空值。资料作者、上传者与判断主张者不是同一个概念。
- 关于谁：`subject_id`，同一 owner + scope 下登记的稳定实体 ID。`records.subject` 保留原始对象文本，不靠同名字符串自动关联。
- 具体主张：`records.statement`。类型与优先级不证明真实性。
- 何时成立：`as_of`；何时不再适用：`valid_until`。两者都要求规范 `YYYY-MM-DD`；失效日期是排他边界，到了该日就不能作为当前上下文。`created` 仅是入库时间，不回填成成立时间。
- 依据在哪：`source_id + message_id + quote`，结合 source envelope 的 `original_ref / locator / original_date / author`。匹配引用不等于概括正确。

未知允许进入候选、历史记录与档案；不能凭名称、别名、导入日期或上传者推断身份和成立日期。同名实体不会自动合并。内置 `owner:<owner>` 仅代表当前归属空间的本人，不允许以注册实体方式覆写该保留身份。

## 思考、建议、决定与经历

沿用现有 `kind`，避免本轮修改公共数据模型：

| 内容 | 现有 kind | 归属要求 |
|---|---|---|
| 尚在探索的思考、分析 | `claim` | 明确是谁的分析，先候选 |
| Agent 或他人建议 | `suggestion` | 保留助手/外部来源身份；不能变成本人决定 |
| 本人明确决定 | `decision` | 需有本人原话或明确批准该具体判断的证据 |
| 未来打算 | `plan` | 不是已发生事实；计划时间不能替代主张成立时间 |
| 会议经历、完成事件 | `event` | 原始记录保留，是否有长期价值单独判断 |
| 偏好、身份、人物关系 | `preference / identity / relationship` | 单次行为不推断习惯；关系不靠模型猜测 |

上述分类帮助治理与检索，不自动改变 `status`（来源归属）、`state`（治理结论）或权限。

## 状态、权限与写入约定

| 状态 | 含义 | 当前可信上下文 |
|---|---|---|
| candidate | 未核实，包括抽取与 Agent 派生判断 | 不进入 |
| verified | 本人经审核确认的判断；holder / subject_id / as_of 必填且实体存在 | active 且时间有效才进入 |
| historical | 保留历史判断，即使曾经成立 | 不进入 |
| rejected | 留痕的错误或不采纳判断 | 不进入 |
| owner_corrected | 旧本人纠正路线的既有兼容状态 | 本轮保留原准入，不自动升级或重写 |

本人审核使用乐观并发 `revision`。本人编辑保留新旧记录取代链与审核事件；metadata 补充不能改变原来源。Agent 无权调用本人审核、直接确认或纠正路线；上游只能提交受权限限制的来源/候选。

共享实现 `judgment_contract.normalize()` 验证字段、状态、规范日期与完整性；`validate_verified()` 验证有效区间和 owner + scope 下实体存在。`governance.review` 使用该契约；`owner_memory` 应复用同一验证，而保留自己特有的 `explicit_confirmation` 配对。契约本身不推断确认，不执行模型，不改旧记录，不在读取时静默写回状态。

未来日期或已经失效的记录允许作为 candidate / historical 留存，但不能审核为“当前有效 verified”。未提供日期不能用今天补齐；已过期旧 verified 由现有读取守卫排除，本轮不批量降级。

## 对真实结构的五问诊断

依据：`core.py` 的 records/sources/events、`governance.py` 的 record_governance/governance_events、`entities.py` 的 memory_entities，以及 owner_memory/retrieval_ranking。这里只诊断结构，不把未核实记录宣称为高质量记忆。

1. **稳定对象：有基础但覆盖不完整。** `subject_id` 支持同范围稳定 ID，verified 入口检查存在；历史记录仍可空且没有物理外键。自由 `subject` 是原始文本而非身份，不自动回填。对未解析来源强行挂实体将造成 FC-01 / FC-08 的张冠李戴。
2. **观点归属：有字段，未知不猜。** holder 与 subject 分开；trusted 的完整审核要求两者均登记。候选缺 holder 不视为本人。否则会出现 FC-03 的助手/外部观点污染。
3. **演变：部分完整。** `supersedes` + lifecycle + event 审核留痕能回查替换版本；`as_of / valid_until` 可表达判断有效期。但缺少明确的 `invalid_at / superseded_by` 查询契约，系统知晓时间与事实失效时间仍不能完整双时间查询。FC-04 风险不能用入库时间或更正事件时间简单消除。
4. **守卫：本轮收敛。** review 与 owner maintenance 原来分别实现日期与实体验证；本轮抽出共享契约，并补未来/过期 verified 拒绝，避免 FC-02 的入口不一致。授权仍在各个调用入口，必须保留，不能以共享业务验证替代授权。
5. **展示反馈：未建设。** 当前没有标准 impression 表。检索排序有静态优先级，不把点击或被采用次数当真值置信度。未来记展示信号之前先确定隐私、保留期与真实评测需求；不能承诺“越用越聪明”。这对应 FC-05 的潜在错误接线，尚未观察到本轮代码产生该故障。

## 按依赖推进的安全增量计划

1. **现在完成，无迁移/回填：** 两个人工写入入口复用结构/时间/实体校验；校验 owner + scope、并发与审核事件，新增合成回归测试。来源类型、角色、候选与可信分离保持原契约。
2. **随后完成，无自动写旧数据：** 建立范围内只读诊断报表，统计 missing holder / subject_id / as_of、已过期、已取代与来源不完整项；人工核对代表样本后再考虑映射。匿名讲话者与泛称保留未解析，不建立猜测实体。旧原子库先作来源审计，不当作已确认个人事实。
3. **冲突处理先仅候选：** 同 holder + subject + scope + 有效期重叠，只能生成待审查冲突组；相似文本不能证明冲突。本人确认替换后才接到版本链。不同人的观点可以不同，不相互覆盖。这里需要语义质量评测，尚未实现自动冲突裁决。
4. **需另行迁移评审的唯一新增结构工程：** 若要回答“当时世界上是否成立”与“当时系统相信什么”，设计有效期与系统期双时间审计字段；先拟 SQL、恢复演练、向后兼容与人工回填规则，再执行迁移。旧更正事件只能证明系统更正时间，不能推断事实失效时间。**本轮没有新迁移，也没有执行生产回填。**
5. **基于需求再加展示反馈：** 先记录最小 impression（返回的记录 ID、范围、时间、方法版本，不存完整提示词），评测后再用于检索展示策略。采纳/点击不改变 verified 或事实置信度。需要新结构时同样单独迁移；不在这次扩展重型图谱或训练系统。

## 可自行验收的检查

1. 在两个 scope 注册同名合成人物：personal 的 verified 不能引用仅登记在 project 的 ID；同名不是同人。
2. 空 holder / subject_id / as_of 审核 verified 必须拒绝，candidate 允许且仍保持空值；原文链接与观点归属应能独立核对。
3. 更正/补充后旧 records 与 governance_events 留存；active 上下文排除已取代版本。事实失效时间未知仍标未知，不误报完整双时间追溯。
4. 搜索日期/当前有效判断的实现：统一入口调用 judgment_contract；独立的 read usable 仍作为读取保护，不承担写入验证。
5. `unresolved:speaker-2` 未登记时不能挂入 verified 实体位；Agent 不能登记实体或确认记录。用户显式登记一个限定对象不等于允许模型自动解析同名对象。
6. 展示记录：目前尚无标准表，故此验收项明确未通过，不以 API 日志代替真实展示事件。
7. 反馈：目前不训练反馈；今后点踩不得改变治理状态或真值，只能进入预先验证的展示策略。

合成回归覆盖非规范日期、未来成立、当天失效、跨 owner / scope 实体、保留身份、非布尔授权、未知不猜、审核留痕及 stale revision。通过这些检查仅证明契约执行，不证明所有历史抽取结论正确。

## 渐进读取的变化检测契约（T06）

`memory_context` / REST context 保持现有 500–16000 字符整包预算与可信准入，新增：

- 顶层 `scope`：本次显式请求的范围，不自动跨范围联查。
- `context_revision`：24 位确定性内容摘要；`etag`：同摘要的带引号形式。它基于 owner、scope、query、检索方法、预算和本次所有合格记录及治理版本计算，包括因预算未返回的合格记录。重复相同读取稳定；更正、拒绝、有效期导致合格结果变化时，摘要改变。
- 每条记录增加 `status`、`subject`、`source_date`；`source_date` 是原消息日期，不是判断成立日期。未知原日期仍空值，`governance.as_of` 与之分开。

这两个版本字段是内容变化检测标记，不是强缓存保证、授权凭据、HTTP conditional request 实现或主动撤权通知。调用时每次重新检查权限；已撤 scope/action 应拒绝请求，不能继续返回旧内容。客户端本地旧上下文如何清理，仍需下游 Skill/Agent 在任务边界刷新与过期处理。

包预算无法容纳整条判断时，返回 `total / truncated` 与空或部分记录，不截断正文、不把候选补入可信结果。空包本身因异常范围标识超预算则拒绝。合成测试同时验证整包预算、来源日期区分、重复稳定、更正及审核变更、隐藏记录变更和撤权拒绝。
