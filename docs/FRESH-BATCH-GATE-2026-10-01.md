# 新材料小批验收前置检查

下一步先用 3 个未出现在指定历史回执中的短材料，冻结来源、输入及验收合同，再独立检查模型结果。本轮只研究候选质量；不写入正式记忆、不恢复历史全量。

## 未见的边界

`scripts/prepare_fresh_memory_batch.py` 从 Claude 可见正文选择完整、未拆分的短消息。选择前排除：

- 历史 metadata 中存在非 `planned` 段的整段对话。
- 提供的所有历史评测输入中出现过的原始消息 ID。

输入带原档案 SHA256、消息 SHA256、旧 metadata 和回执 SHA256。这里的“未见”只相对于这些提供的回执。历史失败或已调用但未留回执的请求、其他 Agent 调用和模型训练内容都不能由本检查证明未见。选样不是随机抽样，本批不能用于推断全库质量。

公开仓库只保存程序、聚合说明和明确标为合成的数据。真实材料与预先合同保存在仓库外的私有目录，文件权限 0600，使用独占创建，拒绝覆盖。

## 流程

1. 排除既有处理与评测输入；人工选出不同目标的短材料。
2. 冻结原始消息与精确定位；仅使用 `text` 块，排除 thinking/tool 块。
3. 在模型输出出现前写 `required_facts` 与 `forbidden_facts`。包含正例和允许空输出的临时任务负例。
4. 先计算每次完整请求的保守预留。由实际调用方在共享预算内逐次预留、调用、结算；达到本批上限即停止。
5. 模型输出解析后检查可见原文、角色、重复、中文展示、源日期和对话范围。
6. 独立审阅每条陈述是否被所选证据完整支持，必需事实有没有遗漏，禁止事实有没有产生。
7. 记录技术检查与 Agent 语义审阅两套结果；当前有效性仍未知，不确认身份、不升格真值。

静态检查通过仅说明满足格式及可机械验证的边界。中文字符存在不代表翻译准确，引用存在不代表推理正确，日期存在不代表现在仍成立。`source_reported` 是历史来源报告状态，不能当成已核实事实。

## 真实调用预算保障

现有 `budget.reserve_request` 以输入、系统提示 UTF-8 字节数、输出上限和 1024 余量预留。正式调用必须使用相同完整请求、相同 `max_tokens`。旧批次预算和新账本共同约束请求；预留失败不能调用。

结算规则：已返回 usage 的请求按实际计量；HTTP 错误、超时、解析错误或进程崩溃未返回 usage 时保留预留，不当作零用量，也不自动重试。返回 usage 但输出不合格的调用仍计费。单次响应意外超过预留时真实计量可能超过本批硬额度，须如实记录并停止；预留是保守估算，不是供应商计费保证。

本批预设最多额外 30,000 tokens；三项预留合计 22,864，最大单项 7,661（以冻结输入和当前提示词计算）。调用方负责生产账本事务及最终关闭样本额度，本脚本不连接数据库、模型或服务器。

## 实施与验证

新增准备脚本包含可复用的 `candidate_gate`，不会自动确认事实或开启生产分发。测试覆盖未见筛选、排除思考内容、已处理/已评测拒绝、原文引用、重复、确认状态拒绝，以及私有文件权限与不可覆盖。

下一步输出真实模型结果和独立审阅回执，将本批作为新增证据；三条样本的通过不能代替扩大质量评测或用户的质量决策。
