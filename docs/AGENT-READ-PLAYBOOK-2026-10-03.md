# 第三轮：轻量 Agent 读取与能力自检

本轮更新仓库中的 Skill 和离线自检，不修改本机已安装 Skill、凭据、线上数据或模型预算。

## 渐进加载

1. 当前任务无需个人背景时不读记忆。
2. 需要背景时，在明确授权范围用 `memory_context` 读取约 1,600 字符。成功但为空，表示没有匹配的可用可信记忆，不以候选填充。
3. 确有证据问题，再调用 `memory_candidate_search` 读取约 4,000 字符的候选窗口。保留归属、治理状态与来源，不将候选升级为本人事实。
4. 需要核对原话且有 `source_read` 权限时，再读一页相关原文；足够作答即停。

预算和次数按任务调整，以上为建议起点。读接口不调用模型；提炼与翻译仍是独立授权、受预算和质量门控制的操作。

## 能力与续读

`--check-tools` 接受本地保存的 MCP `tools/list` JSON，按字段类型和必需参数检测能力，而不是数工具数量。它支持完整 JSON-RPC、result/tools 和工具数组格式。

新增窗口接口缺失或 schema 不兼容时，报告窗口不可用。旧 `memory_search` 可明确用于缩小查询的兼容方式，无分页 offset；不会隐式切换范围或扩大权限。

候选续读使用 `coverage.continue_offset`，其含义是已检查的排名位置，而非已返回记录数量。预算省略的记录可用原 offset 加大预算重读。排名会随写入变化，窗口不是稳定快照；达到 offset 上限时不得猜测后续游标。v2/v3 实验模式可能仍扫描全范围，不能把小响应解释成低后端成本。

## 三种情况必须分开

- 空可信结果：缺少匹配的有效已核实上下文。
- 接口缺失或 schema 不符：功能暂不可用。
- 权限失败：停止扩展、丢弃任务中持有的结果和定位信息；不能当成空记忆或试探其他 scope。

上游 capture Skill 增加约束：空可信结果不是把检索候选重新作为 user 发言导入的理由。

## 验证

- 自检测试共 10 项通过，包含 schema 不兼容、同名错参数、缺窗口旧客户端兼容、缺可信入口、schema 描述脱敏及真实进程内 MCP 的空结果/越范围拒绝。
- `--self-test` 使用合成数据、临时数据库和进程内传输：模型调用与远程网络调用均为 0。
- 两个仓库 Skill 的 `quick_validate` 通过；公开树扫描通过。

这些结果没有证明实际 ArkClaw 或 LocalVault 客户端已接通。真实客户端仍需它们保存的工具清单和实际只读调用回执，不需要在报告里传递 Token。
