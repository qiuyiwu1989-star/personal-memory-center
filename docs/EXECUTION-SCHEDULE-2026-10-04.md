# 记忆中心下一阶段执行计划 · 2026-10-04

## 本轮安排

按“后台可管理 → 提炼可靠 → 小批治理与真实 Agent 使用 → 扩量与多源”推进。第一轮后台发布准备与提炼质量开发可并行；协议准备也可同步进行。恢复 Claude 全量依赖真实质量验收，不能用工程测试替代。

现状：配置与关系视图在 draft PR #5，提交 d6b8654，两次 GitHub 检查通过；生产尚未发布本轮功能。已有 483 项 Python（482 通过、1 项既有 expected failure）、14 项 Node。生产数量与预算沿用上次收据，本计划没有新查库或启动模型。

## 第一轮：先完成可管理与可靠性

### A1 · P0 · 后台发布准备（后台工作包）

对生产稳定 v17 + 撤回补丁准备配置功能兼容补丁，避免把实验 v21 一同上线。审核 008 配置表，在非生产 PostgreSQL 演练迁移、并发启用、撤回/回滚与预算结算；保留发布前后方法、数据、预算与服务指纹。

验收：非本人不能管理配置；跨范围不能启用；任务在途不能切换；既有记忆与暂停批次不被改变；失败能恢复旧版本。完成后安排独立发布与已登录生产页面验收。

### A2 · P0 · 补齐配置管理体验（后台工作包，与 A1 同线）

实际验收 Skill 下载，补版本差异、当前启用配置显示及配置清单分页。增加服务商与密钥的安全配置方案：不回显 key、不进入版本 JSON、不复用旧密钥调用新地址；先完成设计与隔离测试，再启用新的密钥写入入口。MCP / Skill 补发布版本、兼容说明、客户端实际安装版本记录。

验收：草稿、启用、服务端代码发布、客户端安装四种状态清楚；模型调用和失败记录能对应配置版本。密钥修改应由本人通过安全入口完成，不在聊天收集或展示。

### B1 · P0 · 长文与范围修复（治理工作包，可与 A 并行）

把已有分段规划器接到治理开发流程，保留完整原件导航和逐段覆盖；明确哪些文字归档、哪些送入提炼、哪些未处理。修复普通不同项目条件范围，补嵌套引述、第三方发言、愿望/决定、计划/完成和后续更正反例。

验收：既有 expected failure 成为真正通过；新增反例仍拒绝错误升格；不能靠全部返回空通过。完整归档与完整模型输入分别核对。

### B2 · P0 · 真实质量与费用评测（治理工作包，依赖 B1）

固定方法、提示、模型与来源版本。使用完整开发材料提炼并独立评分；核实预留材料独立性，不将已接触材料称为盲测。核对共享预算、在途和未知预留，设置有界试验额度与停止条件。

验收：报告严重误读、遗漏、出处、条件/时间保留、费用与未覆盖部分；观察样本内的严重身份/归属/授权误读不得放行。评测通过不自动确认真实个人记忆。

## 第二轮：做出可用记忆与真实接入

### C1 · P1 · Claude 小批重治理（数据工作包，依赖 B2）

先选择 20 份高价值或受方法变更影响的来源。保留旧候选与方法，重提炼后比较、治理，不覆盖历史。为每份资料显示归档、提炼、治理、可信可用的分别状态、失败和剩余工作。

验收：每批有来源清单、方法+配置版本、质量抽样、已知/未知用量及停止原因。首批通过后才逐步扩大。完成时间在小批实测吞吐与剩余计划确认后估算。

### C2 · P1 · 首批 personal 与纠正闭环（治理/后台工作包，依赖 A1 和质量结果）

建立少量明确有出处、归属和有效时间的个人上下文。高影响身份、关系、授权和更正按原有规则复核；不拿历史候选填满 personal。确定低风险自动准入规则，先用样本评测，再上线自动化。

验收：后台能补充、修改、撤回；更正后两份独立读取凭据获得新状态；旧版可查、失效记录不作为当前事实。可信为空时仍明确返回空。

### D1 · P1 · ArkClaw / LocalVault 接入（接入工作包，协议准备可先做）

ArkClaw 先验证真实实例读取 personal，再独立验证隔离收件箱。LocalVault 校准作者、来源时间、版本哈希、稳定来源键、重复、续传和删除标记。工具权限、Skill 加载策略、写入归属与回执作为同一份接入契约。

验收：真实运行侧成功调用、有出处和版本；重复不重复记；assistant 素材不直接确认；越权被拒绝。服务端模拟请求不能代替真实客户端验收。实例运行侧与登录条件不可绕过。

### D2 · P1 · 检索与成本（检索工作包，真实效果依赖 C2）

对同一批真实任务比较无记忆、原文检索、治理上下文。测更正一致性、出处、归属、时间、遗漏、拒答、全链路 tokens、延迟与服务端内存。优化内部候选近全量读取；保留渐进加载与完整证据预算。

验收：有结果对照和费用账；返回短不能掩盖后台扫描成本；无需背景的任务零读取；相关记忆缺失时不虚构。

## 第三轮：扩量与长期运行

### E1 · P2 · Claude 扩量与资料接入

C1/C2/D 的用途质量通过后，按价值和方法影响逐批恢复 Claude。其他资料现在可先归档与索引；自动提炼先接 1–2 份真实文档/会议，不必等待所有 Claude 完成。所有来源走同一治理规范，适配器负责格式差异。

验收：每个来源可追踪进度、失败、再次提炼与版本；模型费用按实际账本；原子库先做来源映射，不整体提升为个人事实。

### E2 · P2 · 日常运行与可视化完善

补人物/项目入口、变化时间线、资料处理矩阵；在现有字段上增加局部关系展示。补备份恢复演练、删除/撤回对 MD/索引/缓存的传播、异常停止和恢复；最后再建设经历—结果—规则的学习流程。

验收：有实际恢复和纠正证据；不能承诺未验证副本已永久删除。图数据库、向量检索或长期反思 Agent 只有在真实任务收益证明必要时再引入。

- 主线：A/B → C → D 真实使用 → E；D 协议与评测准备可前置。
