## 用户可以使用的功能

1. 后台「提交资料」新增 Agent 候选收件：按范围查看批次与当前状态，进入原文账本，逐条核实、补充和修改。
2. 后台 Agent 凭据管理可显式开启候选提交权限。第三方仅能在单个 inbox 中，为自己归档的来源提交带精确引用位置的候选。现有只读凭据没有自动扩权。
3. MCP 新增 `memory_capabilities`、`memory_candidate_submit`、`memory_changes`，总计 15 个工具。读取端可发现能力及范围权限，在记忆变化后重新检索。
4. 本人仍可审计旧记录；普通 Agent 不能通过旧历史列表获取已撤回的引文。

检查点覆盖当前记录元数据，服务端为 O(N) 元数据扫描，返回字符数有界。它不是事件全量同步、COS 同步或强制清除外部 Agent 旧上下文的机制。候选入库不确认语义、身份及当前有效性，也不调用中心提炼模型。

开发分支上一轮的 620 项 Python、37 项 Node 检查与本次稳定发布包的计数口径不同，不可混算。独立 PG 演练使用合成数据，结束后临时库已清理；私人备份、配置和执行回执不进入公开仓库。

发布前后已有 **900 份来源、2,228 条记录** 的内容校验一致。没有恢复提炼队列、调整预算、变更凭据、调用提炼模型或确认任何个人事实。上一轮本机的 4 份来源、8 条待核实候选仍在隔离工作台，未随代码发布上传生产。

公网测试使用已有只读凭据及正式 MCP SDK；不等同于 ArkClaw / LocalVault 实际运行实例的验收，也没有替用户登录后台。下一步仍是 LocalVault 真实小批接入、显式采纳进入 personal、实际 Agent 更正闭环，再按质量结果扩大治理。
