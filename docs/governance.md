# 完整治理、轻量调用

## 六个环节

1. **原文归档**：原件、哈希、角色、日期、来源键。归档不等于记住。
2. **提出候选**：规则筛选后，必要时 LLM 提炼；留方法版本和用量。
3. **核实归属与证据**：谁认为、关于谁、概括是否由引用支持；逐字匹配仅证明引用存在。
4. **判断长期价值和有效时间**：长期用途、成立/失效窗口、不确定性和冲突。
5. **按任务与权限提供**：先过滤权限与证据状态，再按关联度、有效性去重和限制长度。
6. **纠正与演变**：保留旧版和来源，新版明确取代什么；跨 Agent 新会话读到更新。

## 三个独立维度

| 维度 | 回答的问题 |
|---|---|
| 优先级 | 哪些内容应优先核实和维护？ |
| 证据状态 | 谁提出，概括有多大支持，是否仍适用？ |
| 相关性 | 本次任务需要加载哪些内容？ |

P0 是身份、更正和边界；P1 是关系、长期目标与关键决策；P2 是重复有证据支持的偏好；P3 是讨论、草稿和旧尝试。P0 不自动等于已确认，也不要求常驻上下文。P3 仍可作为档案和内容原子供深度任务查找。

## 最小记忆结构

谁认为（holder）· 关于谁/什么（subject）· 具体陈述 · 何时成立（as_of）· 依据在哪（provenance）。

另保留失效时间、取代关系、方法版本、证据状态与权限范围。稳定人物和项目 ID 只解决必要对象，不建设通用本体。来源日期不等于成立日期，入库时间不能补作成立时间；未知保持未知。助手意见或外部报告不得自动署名为用户观点。

这些是目标契约，0.1 数据模型目前未完整实现。结构化字段扩展必须先迁移、再保守回填，不从模型猜出的名字自动合并身份。

## Agent 加载策略

- 简单、自含任务和新鲜会话上下文：0 次调用。
- 缺少个人背景：一次短检索，保留性质、时间和出处。
- 需要更深背景：定向检索或展开命中的局部内容。
- 冲突、日期不明、高后果判断：核对原话，证据不足就明确未知。
- 当前事实、候选、历史应区分返回；默认不混成一个“事实包”。

字符预算是默认策略，不是所有任务的绝对限额。读取不重新调用模型总结全库；复杂总结可在有变更时异步生成。反馈影响相关排序，不因点击或接受次数提高事实可信度。

## 验收与成本

质量检查：概括受证据支持、主张者不混淆、时间准确、旧版可追、纠正跨 Agent 一致。

成本检查：任务读取量、调用次数、重复提炼率、供应商报告用量以及未知用量。以真实任务比较无记忆、短上下文、按需查原话三种策略；不以记忆条数验收。

治理能接对回路，实际收益仍需评测；规则、实体层或引文校验均不能替代内容质量判断。
