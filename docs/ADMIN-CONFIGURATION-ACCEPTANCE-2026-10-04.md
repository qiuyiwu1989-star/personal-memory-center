# 配置管理第二轮验收 · 2026-10-04

这是本地开发与合成数据验收，不是生产发布或记忆提炼质量认证。本轮没有修改真实数据库、调用模型、调整预算、恢复队列或确认历史记忆。

## 本轮完成

- 配置版本按 20 条分页，服务端允许 1–100 条；返回总数、当前位置和下一页位置。相同时间戳按 ID 排序，单次浏览的每页可明确定位。若同时新增版本，offset 分页可能发生位移，刷新后重新浏览；不是冻结全库快照。
- 启用审计独立按 30 条分页，不再把最近 30 条显示成完整历史。保留前后版本与启用依据。
- 当前启用版本独立读取，不受版本列表分页影响。模型表单从实际启用配置填入接入点与输出上限；无启用版本时使用服务端基础配置。
- 同类配置或同名 Skill 可进行字段文本差异比较；按 owner 和 scope 查找两边版本。显示差异不等于语义质量认证，也不执行 Skill。
- Skill 草稿与随服务代码打包的 Skill 增加下载端点，返回 UTF-8 正文、attachment 文件名和 SHA-256。文件名由受控 Skill 名称与内部版本 ID 生成，不使用用户填写的版本文本。
- 下载端点保持本人 read/write 与 scope 校验、私有 no-store 响应。生产浏览器会话使用服务端 attachment 导航；独立 Token 或 localhost 使用已鉴权的内容 Blob。Token 不写入 URL。
- MCP 页面明确展示此服务的代码契约指纹；Skill 显示“随此服务代码打包”或“草稿”。客户端是否连接、是否安装、实际使用哪个版本均为未知；下载不能把状态升级为 installed。

原有乐观 revision、仅本人管理、启用前检查在途任务与运行批次、服务端模型地址绑定、密钥字段拒绝等约束仍保留。本轮新增路由不会绕过这些约束。

## 合成验收

配置相关 Python 23 项通过（含已有测试与本轮并行运行时配置测试）；本轮新增 5 项测试覆盖：

1. 105 个配置版本全部可分页读取，第一页之外的旧启用版本仍返回完整当前 payload。
2. 33 次切换的审计可读完，不重复、不丢失。
3. 差异精确、跨 owner/scope 及异类配置拒绝，不自动认证语义。
4. HTTP Skill 下载的正文、UTF-8 编码、SHA、attachment、私有缓存与访问控制。
5. 非法分页拒绝，第三方不能管理，客户端安装状态为 unknown。

本地合成浏览器另验证 25 个版本：1–20 → 21–25 翻页、旧版本启用状态、当前启用版本独立显示，以及两份合成提炼提示的实际文本差异。Node 语法检查通过；memory-files 的 3 项测试通过。全仓集成结果由主任务记录，避免把并行中途计数写成最终发布验收。

## 下载和生产验收边界

HTTP 下载路径已验收；Codex 内置浏览器在点击 Blob 下载后未返回 download 事件，10 秒超时。页面成功鉴权并读到内容，不足以证明浏览器文件已落盘。仍需实际浏览器或生产会话确认保存的文件及 SHA。本轮没有无限重试，也没有通过公共链接或放宽鉴权绕过限制。

生产 cookie attachment 导航已实现，但本轮未登录生产做真实下载验收。实际 Skill 安装与 ArkClaw 调用必须分别确认。

## 密钥与新服务商后续设计

密钥保持在服务端私有配置。未来如增设服务商：先独立配置对应密钥与 HTTPS 目标，校验 provider 与地址绑定；界面只展示配置状态和非敏感标识，再允许为该 provider 建立模型版本。连接验证应显式区分不调用模型的配置检查与产生费用的请求测试。不能把当前密钥发给后台自由填写的新 host，也不能把密钥保存到提示词、配置版本、审计、下载文件或公开代码仓库。

这部分是安全设计边界；后台换密钥和多服务商尚未实现。
