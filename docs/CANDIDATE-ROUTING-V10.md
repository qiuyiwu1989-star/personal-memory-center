# 候选分流与关联 v10

本轮方法版本为 `2026-10-01.10`。这些规则只改变模型接收的提炼视图，不改动原始资料、已有候选或治理状态。规则通过不代表语义质量通过。

## 可提炼证据与参考资料

- 对话中的助手稿件与建议路由为 `assistant_reference`，不进入个人长期记忆抽取；原件仍可回查。如果用户明确采用了某项建议，应引用用户的完整采用陈述，不能从“好的/继续”反推详细授权。
- 明确的角色模板、章节大纲作为参考资料。用户先给出外层约束、随后粘贴章节时，使用 `mixed_reference_document`：仅将章节前的外层用户约束作为证据，稿件内建议留在档案。
- 一段消息既陈述系统配置，又提出临时制作任务时，不因临时任务而丢弃配置。系统组合、智能体列表的证据片段带 `priority_hint=explicit_configuration`，提示模型必须审查是否应保留。该标记不是自动生成记忆，也不证明方案已实现。
- 二手摘要继续走独立归属路径，不能因为其消息角色是 assistant 就当成直接助手建议，仍须保留“摘要记载/主张、原始时间未知”。

正文分片仍保持精确偏移，模型只能选择给定证据编号。一次片段最多1000字符；参考正文不会额外发给模型。原件中的正文、附件及排除原因仍需从档案层回查。

## 重复候选只关联

`candidate_links(candidate, records, limit=20)` 是纯函数，不调用模型、不操作数据库。调用端应先限制 owner/scope，并补齐各项的来源类型、角色、状态与 evidence_context。函数再次检查 owner/scope、归属、时间、项目会话范围一致。

- `exact_statement`：在主题、类型、主体一致时，规范化空白后的陈述逐字相同。只是重复表述建议，不增加证据独立性或可信度。
- `same_evidence`：同一个 source_id/message_id/quote 被两个陈述引用。只是共同证据关系，不代表陈述语义等价。

返回原记录ID、关联类型和原证据指针。新旧记录及每个出处保持独立；不推断近义句、同名实体、同一项目，不自动合并、删除或确认。日期或归属不同的材料不建议归并。

## 局限与验收

章节/模板分流是保守模式匹配。没有明确边界的长文不凭猜测切开；小说、例子、配置是否为真实用户决策仍需语义复核。配置提示提高召回优先级，不保证模型一定提取，正例评测仍须检查漏提。

公开测试仅使用合成内容，覆盖助手稿件、用户外层约束＋章节、无Markdown角色规范、明确七智能体配置＋临时任务、重复陈述、多出处、不同归属/日期/范围与输出上限。真实难例需同版本独立评测后才能解除全量暂停。
