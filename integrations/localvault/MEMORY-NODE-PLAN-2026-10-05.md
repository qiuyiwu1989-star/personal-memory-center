# LocalVault 与记忆中心：独立运行、统一规范、双向协作

状态：供 LocalVault 开发者评审的建议方案，不是已经部署的双向同步协议。2026-10-05，评审后修订。它扩展此前“可靠归档”的接入说明，不替换现有 MCP 字段约束。

修订边界：独立产品定位保留；首轮收敛为本地证据节点，不立即新增完整记忆引擎。独立本地提炼是后续选项，须本人确认目标和模型方式。评审方所述既有约束/本机签署数量属于其报告证据，未据此改用户授权或复核真实私有库。

## 1. 产品定位与关系

LocalVault 是本地记忆节点：把授权目录、文档、会议和人与 Agent 的协作，转化为有出处、可检索、可纠正的本地上下文。断网、未接云端时仍可索引、查询、管理与使用已有记忆；处理新候选是否能离线取决于所用模型。

记忆中心是跨设备、跨 Agent 的记忆协调节点：汇集获授权来源和治理事件，管理共享实体、冲突、权限、发布状态与有界检索。对“共享给其他 Agent 的当前个人上下文”，以中心确认的发布版本为准；LocalVault 可以保留独立私有记忆，不要求所有内容入云。

双方不是采集器和总控的关系，而是独立本地产品与可选共享中心的关系。首轮 LocalVault 的独立性由本地检索、证据版本、处置判断和可靠交付实现，不以拥有第二套候选治理引擎为前提。统一规范不等于共用运行进程，也不要求在两端复制所有模型任务。LocalVault 专长在文件与设备，中心专长在多源治理与共享；相同证据不重复算作独立支持。

当前 LocalVault `claims.db` 中对文件/目录/项目的“保留、待看、可归档、可清理”属于资料处置判断，应继续保留。它们不自动变成对资料正文的认同。长期上下文与处置判断分别建模，引用可以关联，不改写旧事件。

## 2. 现状与待建设边界

| 能力 | 已有基础 | 本方案新增 |
| --- | --- | --- |
| LocalVault 本地 | 索引、地图、词法检索、文件体检、追加判断、上游手动归档 | 首轮来源/交付状态与出网检查；本地候选提炼另列后续选项 |
| 中心治理 | 来源与候选、稳定实体、本人治理、纠正历史、有界 MCP 读取、本人来源撤回 | 外部候选包接收、可信本人事件接收、双向增量日志及冲突接口 |
| 来源提交 | memory_import 归档、收据、状态查询与角色保留 | 原件/COS 分阶段上传及完备性对账 |
| 代码兼容 | 中心侧隔离补丁 14 项真实 HTTP 合成检查通过（与 LocalVault 的 84 次假端点断言不同） | 实际安装、小批真实资料、撤回同步验收 |

当前 ordinary writer 只应归档自己的收件范围；不能设置中心治理 verified。memory_import 接收来源，不接收任意候选、签字或同步事件。下面的记忆包和同步消息都是拟议协议，不可直接塞入现有工具的 kwargs。

## 3. 共同记忆方法论

保留原件 → 确定来源与发言者 → 提出候选 → 核对语义、归属、时间与范围 → 治理/确认 → 按任务加载 → 更正与撤回。

每一环都有独立状态。解析成功不表示语义正确；找到引用不表示概括受到支持；模型高置信不表示本人批准；归档成功不表示进入当前 personal。

程序负责权限、格式、来源哈希、版本、去重、分段、回执、检索及状态过滤。LLM 用于可选的候选提炼、语义归属检查、主题组织和翻译；调用需记录方法、输入、费用和结果。不在常规同步和每次读取时调用 LLM。人工确认是治理事件，不是另一次摘要。

### 来源规则

- 本人原话、助手输出、第三方发言分开；上传者不等于作者。多人会议先保留原说话人标签，不按姓名猜实体。
- 原文、录音转写、人工摘要与模型摘要区分表示层；保留来源依赖和未核对 ASR 等限制。
- 原始日期、文件修改时间、导入时间、事实成立时间分开。不得用 mtime 代替事实成立时间。
- 长文连续分段，保留原消息 ID、区间、邻接关系和父版本。不静默截断；上下文不足阻断人物/长期状态推断。
- 中英文原件保持原语言。中文显示或翻译是派生视图，关联原陈述与生成方法，不能替换证据。

### 候选记忆的最低字段（拟议交换模型）

| 对象 | 必须表达 |
| --- | --- |
| 标识 | 节点 ID、本地记录 ID、来源版本、处理运行 ID |
| 五位结构 | holder、subject、statement、as_of、evidence；未知项显式为空 |
| 适用条件 | 项目/领域/用途、条件、有效区间，避免把临时任务概括为长期偏好 |
| 证据 | 来源版本与消息/区间、引用、上下文完整性；不同引用是否同源 |
| 治理 | candidate / verified / historical / rejected、优先级、生命周期、修订号 |
| 方法 | 协议与方法版本、提示词摘要、模型标识、输入/输出摘要及评审限制 |
| 可追溯性 | 创建者、人或机器、产生与记录时间、替代关系和明确更正类型 |

字段是概念模型；当前中心实际字段参见 `judgment_contract.py`。交换模型需要先写 schema 和兼容映射。所有未知身份/日期继续未知；本地显示名到中心稳定实体须有明确映射，不能按同名自动合并。

### 状态、优先级与确认

中心现行治理状态为 candidate、verified、historical、rejected；是否 active、来源是否 withdrawn 是另一个维度。unknown/conflict/context_partial 是评审阻断，不伪造新的既有治理状态。verified 还需归属与主体实体有效、成立日期已知、当前在有效区间且来源未撤回。

P0：身份校正、重要更正、授权边界。记忆中的旧授权不能授予现在的行动权限。
P1：持续关系、长期目标、项目关键决定及理由。
P2：有重复证据支持的偏好与工作方法；单次行为不能直接概括习惯。
P3：会议、草稿、临时任务、旧尝试，通常作为可检索档案。

本人确认仅确认具体版本的具体陈述/范围。用户批准开发或上传，不等于批准全部候选。既有确认不能跨版本盲目继承；模型内容或证据变化后需检查原确认是否仍适用。

## 4. LocalVault 的本地范围：首轮证据节点，后续记忆选项

首轮不新建独立候选库、不增加完整治理/模型任务引擎，也不调用本地或云端 LLM。保留索引、来源版本、同步账本、运行/交付记录及既有 claims 处置判断。现有 ledger 若满足载荷落盘、失败留痕与恢复行为，就承担 outbox 职责，不为名字不同重建一套。

首轮 UI 聚焦资料/正文覆盖、交付状态/回执、处置判断及待撤回项。中心负责候选、共享实体、治理状态、冲突与发布；后续下行可做共享结果镜像，不作为第二个独立确认真源。

若本人确认需要离线本地候选，先评审在现有 claims.db 新增独立表的方案，不将 claims.note/verdict 重解释为长期判断，不改旧 append-only 事件。复用同一库也仍有 schema、Swift/JS 读写、迁移和备份工作，不把同库当作零成本或已实现。新字段 as_of 允许为空，绝不以签署 ts 兜底；不同种类 subject 需要独立语义和映射。

本地模型和云端模型都是后续选项，均不由本方案批准调用。云端模型、中心归档和 COS 上传都须先经过下面的出网闸门；本地模型虽不发送正文到模型服务，仍需评审运行方式、资源成本和调用授权。

MD 是可读导出与主题视图，不是第二份可任意覆盖的治理真源。若允许编辑 MD，导入为新证据/更正提案，不能绕过版本检查直接改已确认事实。

### claims 的可执行映射要求

- verdict 只解释为处置决定；任何值均不得映射为中心 verified。
- note 是处置理由，不能不经评审直接映射长期 statement。
- ts 是签署/记录时间，不能映射 as_of。as_of 未知为空，并阻断当前 verified。
- source_ref 只是证据入口，须能解析到具体来源版本与内容；字段存在不表示证据已核对。
- target + target_type 描述被处置对象，不自动识别为中心已登记的个人/项目实体。
- signed_by/actor_type/authority 保留原值；L1/L2 不自动获得中心本人权限。

### P0 出网授权与脱敏闸门（新增前置）

白名单决定哪些资料可被考虑，不单独保证正文可出网。发送到中心正文、COS 原件或云端模型之前，必须评估发送目的、接收方、字段与原件是否获授权。规则版本和评估结果绑定不可变载荷；检查失败/未知阻断本次发送，不静默放行。

首版采用规则扫描与人工预览，不用未经授权的云端模型“先脱敏”。按规则识别禁止外发信息、生成脱敏派生件并保存原件/派生件映射；自动脱敏不能保证清除一切敏感内容，未知格式和解析失败需人工处理。仅按文件名 denyRead 不足以构成正文闸门。

授权只允许脱敏内容时，原件留本地，不因已脱敏正文可发送而同时上传原件。需要保存未脱敏原件时另有明确原件归档授权。脱敏文本不是原文一手引用；中心接收时保留表示类型、修改区间和不能公开的证据限制。现有字段不够表达时冻结扩展契约，不塞未知字段绕过校验。

出网审计只存接收方、目的、载荷摘要、政策/授权版本、结果及时间，不存密钥和被阻断的敏感原文。对重试也校验当前授权：已撤权不得因为 outbox 曾批准而继续发送。未通过该前置，仅运行不出网的合成联调，不安排真实原文上传。

## 5. 记忆包：处理一次，按证据复用

首轮 LocalVault 只提交获出网授权的来源包。本地先提炼后提交记忆包是后续待评审选项，不是首轮任务。记忆包包含来源清单、候选、处理运行、实体映射提案、治理事件与文件清单；正文按可控分段交付，大原件引用已登记对象。不要只有摘要、没有原证据。

中心先验权限、结构、内容哈希、依赖、方法兼容和证据覆盖。兼容且无冲突的本地候选可保留本地处理结果，不全量再提炼；风险检查与质量抽样仍需要。仅当来源/方法不完整、争议或新任务需重新理解时进入受控模型任务。

机器候选不因上传标 verified 就获信任。本人在 LocalVault 的确认可以作为带身份和版本的事件同步，但当前中心没有可信本地确认接收协议；首版接收后仍待中心本人复核。后续需本人授权绑定设备/会话，校验记录与来源摘要、预期修订、事件唯一性及撤权；设备签名只能证明设备发送，不能独自证明人确实点击批准。

## 6. 同步协议与一致性（待开发）

采用本地主动 HTTPS 增量同步，无需给电脑开公网端口。MCP 服务 Agent 的操作与查询；自动同步由确定性客户端执行，不让 LLM 每次指挥网络事务。第一版可复用现有归档 MCP，完整同步使用后续冻结的版本化服务契约，不先杜撰已上线的工具名。

### 上行：本地向中心

1. 白名单变化检测，形成不可变来源版本及包；先持久化现有 ledger/outbox，出网闸门通过后发送。首轮手动试点，自动调度另行评审。
2. 原件需要云端留存时，经中心授权上传私有 COS，校验哈希/大小/对象绑定，再提交可见正文。原件上传与正文入库分别记完成状态，不存在跨 COS/数据库的天然原子事务。
3. 先确认来源收据，再提交依赖它的候选/事件；中心分阶段回执。source archived、candidate accepted、governance applied、context published 四种语义不可混淆。
4. 所有必需分段核对后推进该版本游标；失败保留阶段与可重试载荷。源文件变动生成新版本，本地删除生成待撤回意图。

### 下行：中心向本地

1. 拟新增权限内的增量变更日志，返回 cursor、实体映射、接收结果、中心修订、更正/撤回与冲突；没有该接口时不得伪装成已有双向同步。
2. 本地事务应用一页事件并保存 cursor；事件 ID 去重，断点继续。首次全量快照需绑定一致性游标；游标失效返回需重新对账，不能跳过未读事件。
3. 不全库下载所有云端原件；按选择拉取记忆及必要证据。原件下载另做授权，私有记忆不被共享列表暴露。
4. 本地私有记录与中心共享镜像区分。中心撤回使共享镜像退出当前检索，不静默删除独立本地私有证据。已经交付给其他 Agent 的上下文无法远程抹除。

### 幂等、冲突、权限

来源摘要识别内容版本，但不能抹去多来源的真实独立性。拟议事件幂等键包含 owner、node、事件 ID；固定 payload 摘要，同 ID 不同内容必须冲突。当前来源导入仍按现有 owner/scope/principal/key/digest 去重，换 principal 前先对账。

治理变更携带预期修订号。两端同时修改时保留两项提案，显示差异并等待有权限的人处理；不用“最后写入获胜”改长期判断。不在共享中心接受本地 claim 等级直接映射中心 verified。

写授权限于 inbox；personal 读取独立只读凭据。共享治理/撤回需要本人权限或未来可信事件通道。Token 轮换/撤权必须退出旧缓存，不能自动换 scope。源文件删除不等于远端撤回，撤回不等于物理擦除。

电脑离线仍可使用本地资料和私有记忆；共享缓存标注最后同步时间、版本和未验证新鲜度。涉及重要更正/授权边界的任务优先刷新，刷新失败明确状态，不宣称缓存最新。

## 7. COS、数据库与成本

LocalVault 保留原件、版本与 outbox；中心获授权的大原件放私有 COS，数据库保存可检索正文、定位、对象摘要、候选、实体、事件和状态；系统盘只放程序、临时解析与缓存。短文本首版可先完整存来源正文，原件归档状态单列。

上传授权以限定对象、大小和期限的机制设计，不把整桶管理密钥发给 LocalVault。没有原件上传契约前，COS 自动同步尚未完成。哈希去重限同一授权域，避免跨用户存在性泄漏；对象未登记/解析前不能声称 MCP 可检索。

扫描、归档、同步、索引、规则校验、当前状态读取无需 LLM。语义提炼、可选评审/翻译消耗 tokens；两端相同运行结果复用，中心不默认再做同样提炼。检索先少量 context，再必要原文；不把全库或完整地图作为每轮常驻上下文。费用与质量分开报告。

## 8. 开发工作包与顺序

| 顺序 | LocalVault 开发 | 中心开发 / 双方协作 | 完成标准 |
| --- | --- | --- | --- |
| P0-0 出网闸门 | 目的/接收方/载荷授权、规则扫描、预览、脱敏派生件、出网审计 | 表示层及来源映射契约、接收目的/权限对齐 | 禁止/未知内容不发送；原件上传单独获授权 |

| P0-2 冻结映射 | claims 映射、来源/表示层 schema、状态图 | 联合 fixtures 与字段/权限映射 | verdict 不映射 verified，ts 不映射 as_of，未知不补 |
| P1-1 中心处理 | 交付来源与完整性限制；展示回执 | 中心候选提炼、治理与真实质量评测 | 语义与工程双轨通过；不建设第二套候选引擎 |
| P1-2 下行镜像 | 中心结果缓存、cursor、新鲜度与待撤回状态 | 权限内变更日志、修订回执和冲突接口 | 共享镜像不覆盖独立本地判断；重复/乱序/断点可恢复 |
| P1-3 原件归档 | 经闸门的文件清单与上传状态 | COS 限定授权、登记/校验与失败补偿 | 未授权原件不上传；正文/原件分别对账 |
| 可选 本地候选 | 本人决定后，先评审 claims.db 同库扩展、本地模型及治理需求 | 方法兼容、候选包接收与真实评测 | 不新建独立库、不改旧事件、不复用处置签字确认正文 |
| 可选 可信本人事件/自动化 | 本人决定后评审身份绑定、调度与多格式 | 接收事件、撤权及重放防护 | 不能由普通 writer 或设备签名冒充本人确认 |

出网闸门与兼容工程可先用合成资料并行设计；真实资料发送依赖闸门、权限和可靠回执。首轮不全库同步、不无人值守生产同步、不调用 LLM。中心已有提炼能力不等于这份方案授权新试跑；来源获准出网也不等于获准转交模型服务。

## 9. 验收与交付清单

工程验收：真实实例初始化与权限；长 Unicode/转义文本重组；截断/附件缺失可见；工具错误不记成功；未知结果相同载荷重试；重启恢复；同键异内容冲突；两端并发修改；跨实体同名不误合并；撤回与缓存失效；撤权/轮换；原件上传成功但入库失败及反向失败的恢复。
