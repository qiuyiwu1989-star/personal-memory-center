# 给 LocalVault 开发者：与邱懿武记忆中心的配合说明

LocalVault 负责本地资料选择、解析、原件保留和可靠同步；记忆中心负责统一归档、候选提炼、证据治理、版本更正及面向其他 Agent 的检索。不要在两端各维护一套“已确认个人记忆”。本说明是协作交付要求，不代表已配置生产授权或已验收真实安装。

## 第一阶段：先做到可靠归档

先审阅 [兼容补丁](compatibility-73be498.patch)及 [复测说明](README.md)。补丁基于 `73be4988553be167ea7073458b1f2bc70ab5a3af`；若代码已变动，请迁移修复并对最新提交重新验收，不强行套用旧补丁。隔离副本已通过 14 项真实 HTTP 合成检查，尚未验收用户实际实例。

连接地址为 `https://qiuyiwu.com/api/memory/mcp`，Streamable HTTP，使用独立 Bearer Token。现有客户端环境项为 `LOCALVAULT_MEMORY_ENDPOINT` 和 `LOCALVAULT_MEMORY_TOKEN`。Token 存本地受限环境或密钥存储，不写进仓库、原件、收据日志或交流回复；不是模型 API Key，也不是网站登录密码。

建议独立收件 scope `agent:localvault-inbox`，写凭据仅授予该范围归档及必要的状态读取，`archive_only=true`、`trusted_user=false`。这是待配置的目标，不是现成 Token。读取 personal 另用只读授权，不把 personal、Claude 历史写权限塞进同一 writer。

保留已有 `~/.localvault/upstream-manifest.json` 白名单机制。第一批只选 3–5 份已授权资料：本人明确决定、含第三方发言的会议、后续更正，以及一份长文；允许兼有这些特征。未明确的作者不能自动标 user，上传者不等于会议发言者。author/日期未知时保留未知，不填猜测值。

每个来源提交：稳定来源键、具体版本、原角色和正文、原日期（已知时）、原文定位、解析器版本。扫描文件变化无需 LLM；不得先用摘要替代原文。摘要确需送入则标 imported_summary，助手内容标 assistant。附件未解析、ASR 未核对或上下文不完整要在本地清单和联调报告保留限制；不虚构已获得完整来源。

调用 `memory_import` 使用 `processing_policy=archive`。分段保持连续字符区间、角色及父来源，父键放 `source_metadata.parent_source_key`。当前约束和完整字段以工具 schema 与 [导入契约](../../skills/memory-capture/references/import.md) 为准。

## 第二阶段：双方对账，而不是看到成功就算完成

LocalVault 维护不可变 outbox 与同步账本。只有工具未返回 isError 且获得有效 `id/job_id` 回执，才能认定该批已收件；归档状态不表示已提炼、已核实或已进入 personal。

一份长文对应多个中心来源 ID，逐批保留回执，所有批次完成才能推进相应版本游标。断网或超时是结果未知：保留完全相同载荷和身份重试，不能换来源键制造副本。HTTP 200 也可能是权限/校验错误，不能误记成功。Token 更换导致 principal 变化时先对账，不能承诺跨身份全局去重。

文件修改创建新版本；不得覆盖旧判断。文件删除生成待撤回项，不表示中心已删除。当前中心撤回是本人权限，普通 writer 不能执行；中心本人完成逐来源撤回并核对回执后，本地才标远端撤回。撤回保留历史，不承诺物理擦除或远程删除 Agent 已缓存的文本。

首次真实联调请交付不含正文和密钥的报告：

| LocalVault 提供 | 中心负责核对 |
| --- | --- |
| 实际代码提交、Node 版本、运行方式；凭据是否配置（布尔值） | 初始化、工具 schema 和权限边界 |
| 白名单条目数量、来源类型及声明角色；稳定键/定位格式 | 来源路由与角色语义，不把上传者当作者 |
| 每个版本/分段的载荷摘要、回执 ID、任务状态、游标 | 中心归档记录、重复收据、缺失批次 |
| 错误、断网重试、修改版本和待撤回记录 | 不误记成功、不丢版本、撤回后读取失效 |

联调数据与来源 ID 仅在私有通道/本地受限报告使用；公开报告只留合成样例及聚合结果。不要把私有路径、正文或 Token 发进公开 issue。

## 第三阶段：接入记忆治理与按需读取

记忆中心接到原文后，统一进行候选抽取、发言归属、主体/时间/范围核实与长期价值判断。提炼与治理会有版本、费用和质量记录；来源归档不自动触发外部 LLM。模型质量通过也不等于本人确认所有事实。

LocalVault 读取记忆时采用 Skill + MCP：只有当前任务需要个人背景才检索，先取得少量匹配上下文，再展开必要证据，不把全部主题文档每次灌入提示词。空 personal 明确显示“暂无可用个人记忆”；不能自动把历史候选当已确认事实补上。需要查历史证据时使用被授权的候选/档案读取，并标出其性质。

本人决定、助手建议、外部观点分别捕获，作为带出处的新证据进入收件范围。助手不能把自己的建议写成本人已决定；后续更正必须关联原来源/版本。其他 Agent 读取时由中心给出可用状态、依据及变化信息，客户端按授权和上下文版本更新缓存。

## 现在各自做什么

LocalVault：迁移修复、保留白名单和 outbox、提供实际实例的版本/运行入口，完成少量真实来源的可靠交付。

记忆中心：准备独立收件授权、核对真实收据和权限，完成小批语义质量评测与治理，管理个人记忆更正和检索。授权配置与实际资料写入在联调时单独留痕。

共同验收：原文可回查、长文无损、角色不混淆、重复不重复归档、失败不推进、改动另存版本、撤回有回执；再验收提炼质量与当前记忆使用价值。前一组是交付质量，后一组是记忆质量，两组都需要通过。
